# 설계 의도 질의 (DQ-ID) 양식

> 회로를 훑다 나온 "왜 이렇게 설계했나"를 추측으로 채우지 않고 사용자에게 묻는 양식.
> 규칙은 `../규칙.md` §3. 이 질의 리스트는 step 2 산출물이며, 사용자 ★ 응답 자리로 넘어간다.

---

## 1. 언제 질의를 뽑나

세 자료(netlist·도면·BOM)를 대조하다 **A가 판단할 수 없는 설계 의도**가 나오면 뽑는다. 예:

- 세 자료가 서로 어긋난다(미실장·표기 불일치·연결 누락).
- 관행과 다른 결선인데 의도인지 실수인지 알 수 없다.
- 부품 정체·값이 `TBD`이거나 확보 불가라 진행 방향을 사용자가 정해야 한다.

> A는 **묻고 나란히 놓는 데까지**만 한다. 오류다/아니다 판정은 검증자 몫.

## 2. DQ-ID 양식

질의 하나 = 파일 한 블록. `output/질의/설계논리질의_<모듈명>.md`에 모듈별로 모은다.

```markdown
### `DQ-<모듈>-<NN>` — <한 줄 제목>

| 항목 | 내용 |
|---|---|
| 대상 | <노드·부품·네트 — netlist 식별자로> |
| 질문 | <무엇이 어떻게 보이는지 사실 + 무엇을 묻는지> |
| A가 파악한 범위 | (a) <가능한 해석 1><br>(b) <해석 2><br>(c) 기타 |
| 미응답 시 영향 | <이 질의가 안 풀리면 어느 가설·계산이 막히는가 (H-N·Q-ID)> |
| 관련 | <H-N · Q-ID · 데이터시트 근거> |

#### 사용자 응답

<사용자가 여기에 append. 선택지 번호만 적어도 됨>

#### A 회신

<역질의였을 때 A가 되돌려준 요지 — 있을 때만>
```

## 3. ID 규약

- `DQ-<모듈>-<일련>` (예: `DQ-M4-01`). **한 번 준 번호는 재사용·재배치 금지**(`../규칙.md` §2).
- 응답이 오면 **응답 칸·회신 칸은 원문 그대로 보존**(회차 보존, 공통규칙 §4). 판본이 바뀌어 노드 번호가 달라져도 그 칸이 명시한 판본 기준으로 둔다.
- 미응답 항목은 `의도 미확인`으로 표기하고 그 항목만 보류 — 나머지 분석은 진행한다.

## 4. 응답을 심층 분석에 반영할 때

- 사용자 응답이 "오류다"였으면 **설계오류목록의 사용자 확인 오류 절**로 인덱스한다(`../규칙.md` §7).
- 응답이 설계 의도 확정이면 **논리 정합성 대조**에서 [의도] 잣대로 인용한다(`03.데이터시트대조와_가정색인.md` §논리 정합성).
- 응답 안에서 두 진술이 어긋나면(예: "필요한데 빠졌다" vs "필요없다고 봤다") **A가 어느 쪽인지 정하지 않고** 그 사실만 남긴다.
