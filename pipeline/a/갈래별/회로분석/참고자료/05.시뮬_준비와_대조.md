# 시뮬 준비와 대조 (수동 시뮬 루프)

> 정량 동작을 추론만으로 확정하지 않는다 — A가 준비 → 사용자가 수동 실행 → 검증자가 대조.
> 규칙은 `../규칙.md` §6. 자동 시뮬 도구는 없다. 시뮬 실행은 사용자 몫.

---

## 0. 한눈에

```
[A] 모델·자극 준비        →  [사용자] 수동 시뮬(OrCAD/LTspice)  →  [검증자] 추론↔시뮬 대조·판정
 기대 동작점 + 자극 사양       결과(.raw/파형/로그) 회수              기대 vs 실제 → 판정
 + 관찰점(netlist 노드)        (★ 시뮬 결과 회수)                (검증자 단독)
                                     │
                          불일치 시 ← 범인 3택(분석/모델/자극) → R{N+1} 반복
```

## 1. [A] 준비물 (사용자에게 넘기기 전)

기존 4단계 A가 사용자가 **그대로 돌릴 수 있는** 형태로 `output/모델/<모듈명>_시뮬사양.md`에 쓴다. 별도 단계를 새로 만들지 않는다. 준비 사양의 제출 판·지문과 사용자 실행 결과를 연결한다.

| 준비물 | 내용 |
|---|---|
| 기대 동작점 | 노드별 기대 전압/전류/주파수 (A의 정량 동작점 표) |
| 자극 사양 | 입력 소스·파형·주파수·진폭 |
| 해석 설정 | transient/AC/DC + 시간·주파수 범위 |
| 관찰점 | netlist 노드명 리스트 — **식별자와 1:1**로 대조 가능하게 |
| 모델 | 데이터시트 미가용 부품은 가정 명시 + `Q-ID` |

### 1.1 사양 판과 가설·결과 연결

| 필드 | 남길 내용 |
|---|---|
| 식별 | Task·모듈·회차 R·사양 리비전·제출 시각·사양 경로/SHA256·바탕 입력 판 |
| 대상 | H-N·관련 Q-ID·분석 동작점 표의 위치 |
| 기대값 | 노드별 전압/전류/주파수·단위·조건·계산 출처와 미확정 |
| 자극·해석 | 소스·파형·진폭/주파수·시간·초기 조건, 해석 종류/범위·필요 모델/설정 |
| 관찰 | netlist 노드명·끝점/관찰 의미·가설 예측과의 대응 |
| 모델 | 모델 파일/판·출처, 가정 Q-ID와 적용 한계 |
| 결과 인계 자리 | `output/시뮬/` 아래 회차/항목별 결과·파형·로그 경로, 사용 사양 판·실행 도구/버전·설정/일시를 남길 칸 |

사양 판을 고치면 앞 판을 보존하고 새 판/지문과 이유를 남긴다. 서로 다른 사양 판의 결과를 같은 실행으로 합치지 않는다. 실행 전 결과 칸은 미완/미수행으로 두며 기대값을 실측 결과처럼 채우지 않는다.

## 2. [사용자] 수동 실행

OrCAD PSpice 또는 LTspice로 실행 → **결과 산출**: 파형 데이터(.raw/텍스트) · 파형 이미지(.png, 관찰점·축 라벨 보이게) · 로그(.log/.out). `output/시뮬/` 에 회차·항목별로 적재한다. 사용한 사양 경로·판/지문·H-N/노드, 실행 도구/버전·설정/일시와 결과 파일을 함께 남긴다. 사양과 다른 설정이나 누락/실패는 별도 기록한다.

## 3. [검증자] 대조 (검증자 단독)

Z는 5단계 및 B 읽기 배정에 `output/모델/`의 준비 사양/기대값과 `output/시뮬/`의 결과 양쪽 경로·판을 연결한다. B가 기대 동작점·가설 예측과 시뮬 결과를 맞댄다. **A는 독립 대조·판정을 하지 않는다.** 사용자 결과가 없거나 사양 판을 연결하지 못하면 그 사실을 남겨 필요한 결정을 돌린다.

## 4. 불일치 = 범인 3택

추론과 시뮬이 어긋나도 **"분석이 틀렸다"고 단정하지 않는다.** 범인을 먼저 가린다.

| 범인 | 점검 | 다음 회차 수정 |
|---|---|---|
| ① 분석 | 수식·동작 원리·노드 매핑 재검토 | A: 추론 정정 |
| ② 모델 | 가정값(`Q-ID`) vs 실제 부품 특성 | A: 모델 정수 정정 |
| ③ 설정·자극 | 자극·해석 타입·수렴 설정 | A: 자극 사양 정정 / 사용자: 재시뮬 |

- 기본: 시뮬을 정답지로 삼되, **분석이 타당한데 어긋나면 모델·설정을 우선 재점검**(분석 맹신·시뮬 맹신 양쪽 회피).
- 어느 범인이었는지가 다음 회차 수정 방향이다.

## 5. R{N+1} 반복

불일치 → 범인 3택 → 해당 주체 수정 → **같은 작업단위(모듈·가설) 고정 + 회차만 `R{N+1}`**로 올려 재시뮬(공통규칙 §4). R1→R2 비교로 정확도가 수렴한다. 이전 회차 산출물은 미터치 + append.
