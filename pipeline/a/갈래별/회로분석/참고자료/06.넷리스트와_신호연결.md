# 넷리스트 형식 · 신호 연결 · 판 전환

> 회로분석 1~3단계와 입력 판 전환의 기록 양식. 규칙은 `../규칙.md` §1·§3·§4, 정격/기능 출처는 `03.데이터시트대조와_가정색인.md`에 연결한다.
> 실제 회로에서 관찰한 것과 미확정을 남긴다. 이 문서는 특정 exporter의 핀 순서를 미리 정하지 않는다.

## 1. 착수 때 실제 형식을 기록한다

한 담당이 `output/분석/넷리스트형식.md`를 작성한다. 원 입력을 바꾸지 않고 경로·판·bytes·SHA256를 고정한다. 형식을 모르는 상태에서 공백을 합치거나 빈 필드를 버린 토큰 수를 핀 수로 대신하지 않는다.

| 기록 구분 | 남길 내용 |
|---|---|
| 원본·도구 | 입력 파일/판·bytes·SHA256, 문자 인코딩 관찰, exporter 이름/판·설정·출력 형식의 원출처 또는 미확정 |
| 실제 표본 | 파일의 원 행·행 번호 또는 바이트 오프셋, 원문 그대로의 사본과 별도의 공백/탭 가시화·hex 표본. 가시화 표시법을 명시하고 원문과 구별 |
| 필드 경계 | 소자명·핀/노드 필드·부품 값 시작/끝을 구별한 근거, 값 안 공백/탭·따옴표·연속 구분자 처리 |
| 빈 자리 | 내부 연속 공백뿐 아니라 빈 선두·말미 핀 필드, 값 바로 앞 무접속 자리의 원 표본·해석·미확정 |
| 패키지·핀 수 | BOM/도면/DS의 패키지·물리 핀/볼 수와 출처, 측정된 필드 수, 차이와 가능한 이유 |
| 자리↔핀 순서 | 내보내기 순서의 근거(원 CAD 라이브러리/설정/형식 정의 등), 자리→핀/볼 대응표의 출처·범위·미확정 |
| 표본·도구 관찰 | 사용 파서/명령·판·환경, 알려진 표본 또는 별도 수단 대조, 실패와 수정, 미해석 입력 |
| 한계·대체 | 아직 모르는 형식/순서·영향 연결, 추가 원자료/대체 수단·필요 결정 Q-ID |

공백/탭/빈 필드의 표현과 값 경계는 **실제 출력 형식에서** 판단한다. 예를 들어 공백을 단순 분리하는 방법이 팬아웃 검색에 쓸 만해도 핀 자리 귀속까지 그대로 보장하지는 않는다. 핀 수 일치와 몇 기준점의 일치는 부분 근거이며 전체 매핑의 충분한 근거가 아니다. “문자열 정렬”을 모든 도구의 일반 규칙으로 두지 않는다. 전체 대응 근거가 없으면 가설/부분 확인·미확정을 구별한다.

바이트 관찰은 `../../../공통규칙.md` §5.1을 따른다. 형식/파서 변경은 아래 §3의 연결 재추적에 반영한다.

## 2. 배정 신호의 양 끝과 모든 분기를 펼친다

먼저 망 종류를 전원/수동망과 신호망으로 구분한다. 모듈 분석 문서의 “신호 연결” 절에 아래 두 표를 신호 ID로 연결한다. 하나의 노드에 둘보다 많은 끝점이 있으면 끝점마다 행을 추가해 모든 분기를 드러낸다. 부품을 거쳐 다른 노드로 이어지는 분기도 소자/핀과 앞뒤 노드를 연결한다.

### 2.1 신호·망 표

| 신호 ID | 보조 이름(TX/RX 등) | 입력 판·노드 | 망 종류 | 모든 끝점/분기 ID | 설계 의도와 출처 | 깊이·제출 단계·미확정 Q-ID |
|---|---|---|---|---|---|---|
| `<고정 ID>` | `<어느 장치 기준인지 또는 불명>` | `<파일 판/지문·노드>` | `<신호/전원/수동망>` | `<아래 표의 모든 행>` | `<사양·DQ 응답·원문 위치>` | `<Task 사양과 현재 한계>` |

### 2.2 끝점·분기 표

| 끝점/분기 ID·신호 ID | 소자·핀/볼·노드 | netlist/도면/BOM 원문 위치·판 | 자리↔핀 매핑 근거 | DS 문서·판·페이지/표·핀 기능 | 가능한 다중화 기능 | 선택 모드·근거 | 출력 활성 조건·외부 구동 | 미확정·영향·대체 확인 |
|---|---|---|---|---|---|---|---|---|
| `<한 끝점당 한 행>` | `<핀 불명은 Q-ID>` | `<행/오프셋·시트/좌표·BOM 행>` | `<§1 대응표 위치>` | `<실제 기능 출처>` | `<가능 기능 목록>` | `<관찰 자료 또는 불명>` | `<조건별>` | `<Q-ID와 관련 H-N>` |

핀 기능·실제 연결·설계 의도는 각각의 출처로 확인한다. 신호 이름은 보조 식별자이며 이름만으로 방향·의도·선택 모드를 확정하지 않는다. 데이터시트의 가능 기능과 실제 선택된 모드를 구별한다. 선택 모드/핀맵 근거가 없으면 그 칸은 미확정과 Q-ID로 남기고 영향·대체 확인을 연결한다. 자료에 없는 값을 억지로 채우지 않는다.

### 2.3 구동 조건 기록

| 조건/상태 | 기록할 끝점 동작·확인 후보 |
|---|---|
| 일반 단방향 신호 | 해당 조건의 출력·입력과 실제 연결 근거를 나란히 기록 |
| 양방향 | 방향 전환 조건·각 방향의 구동/수신 끝점과 근거 |
| 오픈드레인 | 해제/구동 조건·풀업 등 수동망·공유 끝점·외부 구동 |
| 3상태 | 출력 활성/고임피던스 조건과 시간/모드 근거 |
| 외부 장치 구동 | 커넥터·외부 구동원과 제공된 사양/미확정 |
| 출력 0개 또는 복수 | 조건별 확인 후보로 남김. 곧바로 부유/충돌이라고 확정하지 않음 |
| 핀 기능·선택 모드 불명 | Q-ID·영향 연결·시도/대체 수단·필요 결정을 인계 |

깊이 L1/L2/L3와 제출 단계별 허용 미확정 범위는 각 회로 Task 사양에서 정한다. 기존 깊이 정의(`01.모듈분해와_깊이.md`)를 모두 전수 정량 분석으로 바꾸지 않는다. 표 작성·후속 등록을 현재 필요한 확인의 완료나 독립 판정으로 쓰지 않는다.

## 3. 판이 바뀌면 영향 연결을 재추적한다

입력·파서·핀맵이 달라진 연결과 이전 미확인 연결은 다시 추적한다. 이전에 확인된 불변 연결을 재사용할 때도 아래 근거를 연결한다.

| 연결 ID | 전후 입력 판·경로/SHA256 | 전후 파서·핀맵 판/지문 | 전후 양 끝·모든 분기의 소자/핀·노드 | 전후 선택 모드·활성 조건 | 재추적 결과 위치 또는 재사용의 불변 근거 | 이전 확인 출처·미확정 |
|---|---|---|---|---|---|---|
| `<§2 연결 ID>` | `<이전→현재>` | `<변경 또는 불변 출처>` | `<원문 위치 포함>` | `<근거 포함>` | `<실제 수행/재사용 구별>` | `<보고서/관찰 판·Q-ID>` |

| 조건 | 다음 기록 |
|---|---|
| 입력/파서/핀맵 변경이 연결에 영향을 줌 | 해당 연결을 다시 추적하고 새 원문·핀 기능/모드 근거를 연결 |
| 앞 판에서 미확인 | 이전 서술을 확정으로 승계하지 않고 재추적·대체 확인 결과 또는 남은 Q-ID 기록 |
| 확인된 연결이 불변 | 전후 양 끝/분기·모드·입력 판·불변 근거와 이전 확인 출처를 남겨 재사용 |
| 영향 여부를 결정할 자료가 없음 | 불변으로 취급하지 않고 미확정·영향·필요 자료를 Z에게 반환 |

노드 번호가 같거나 현재 입력에 존재한다는 사실만으로 연결 보존을 입증하지 않는다. 반대로 근거가 있는 불변 연결을 매회 수작업 전수 분석하도록 강제하지 않는다. 이전 판·기록은 지우지 않는다.

## 4. 인계와 범위

미확인 항목은 Q-ID, 확인 못 한 사실, 영향 신호/모듈/H-N, 시도/대체 수단, 필요한 결정으로 `03.데이터시트대조와_가정색인.md` §2.1에 연결한다. 실제 담당·회차·중단/수락은 Z·사용자가 정한다. 시뮬이 필요한 가설은 `05.시뮬_준비와_대조.md`의 사양 판·노드·H-N/결과 경로와 연결한다.

이 양식은 특정 프로젝트의 UART 결선·전체 핀맵·펌웨어 모드·ERC 결과를 확인한 기록이 아니다. 실제 자료와 권한이 배정된 회로 Task에서 채운다.
