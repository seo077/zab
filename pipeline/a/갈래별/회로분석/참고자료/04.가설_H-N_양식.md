# 가설 H-N 양식 · 설계오류목록

> step 4 오류·가설 도출의 양식. 규칙은 `../규칙.md` §5·§7.
> 가설을 세우고 그것을 가릴 측정/시뮬 매핑을 설계하는 데까지가 A 몫. 판정은 검증자 단독.

---

## 1. 가설 표 (표준 필드)

오류·위험 후보는 전부 `H-N` 번호로 누적한다.

| 필드 | 설명 |
|---|---|
| `H-N` | 가설 번호 (한 번 주면 재사용·재배치 금지) |
| 가설 내용 | "무엇이 어떻게 이탈/고장했다"는 한 문장 |
| 회로 영역 | 관련 모듈(`M#`) + 블록·부품 위치 |
| 확인 수단 | 이 가설을 가릴 측정점·시뮬 항목·넷리스트 근거 |
| 우선순위 | 높음/중간/낮음 — 영향 범위 × 발생 가능성 |
| 검증 의존 | 선행 확인이 필요한 다른 `H-N`·`Q-ID` |
| 판정 | **`잔여`/`후보`까지만** — 기각/확정은 검증자 |

> 판정 낱말(`PASS`·`FAIL` 등)을 쓰지 않는다(공통규칙 §2 G-5 보강). 검증자가 산출물을 훑을 때 헛걸린다.

## 2. 좁힘과 보존

- 초기 다수 가설 → 회차마다 측정/시뮬로 좁힌다. **기각된 가설은 지우지 말고 취소선 + 근거 보존**(회귀 방지, 공통규칙 §4).
- 가설 하나당 그것을 가릴 확인 수단이 있어야 한다. 매핑 없는 가설은 "확인 수단 미설계"로 별도 표기.

## 3. 설계오류목록 — 두 절을 섞지 않는다

`설계오류목록_<프로젝트명>.md`는 성격이 다른 두 묶음을 **절을 갈라** 담는다.

| 절 | 내용 | 지위 |
|---|---|---|
| §1 사용자 확인 오류 | 사용자가 "오류다"라고 회신한 항목 | 사용자 회신을 **사실로 인용**. 오류 확정 |
| §2 잔여 가설 | A가 등재한 확인 필요 리스크(`H-N` 잔여) | **미판정**. 오류인지 여기서 정하지 않음 |

- §2 항목이 실제 오류로 확정되는 것은 **검증자 판정 이후**다.
- 각 오류 항목에 **수정 시 영향 범위**를 적어, 나중에 일괄 수정할 때 바로 쓰게 한다.
- "현 라운드에서는 수정하지 않고 현 상태 그대로 분석"이 사용자 방침이면, 결선 사실만 갱신하고 "해소됐다"는 판정은 쓰지 않는다.

## 4. 통합 문서에 종합

모듈별 `H-N`을 통합 분석 문서(`회로분석_<프로젝트명>.md`)에 모아 **가설 종합 표 + 커버리지 격자**로 낸다.

- 커버리지 격자 = 모듈(행) × 확인 축(열). 빈 칸 = 아직 안 본 조합(공통규칙 §6 빠짐 점검).
