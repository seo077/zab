# 규칙 — 엑셀작업 갈래

> 엑셀(xlsx) 작업을 하는 A(레이아웃 A · 출력 A)가 지킬 것. 파이프라인 정의는 `z/pipelines/엑셀작업.md`.
> 갈래와 무관하게 늘 지키는 것은 `a/공통규칙.md` 에 있다. 여기엔 **거기에 없는, 엑셀작업에서만 되풀이되는 것**만 적는다. 둘이 어긋나면 공통규칙이 이긴다.
> 근거: `01. 최초부팅 및 디버깅/log/AI 논의사항.md` Round 7 — D-58(공통 규칙 · 도구) · D-59(두 단계 · 스킬 · G-1~G-9) · D-60(G-10 · 중첩형 스킬 · G-12) · D-61(G-14 · G-16 · G-17) · D-62 · D-64(취향 파일) · D-70(바탕 없이 새로 만든 작업본의 원래 값 = R1 판). 되풀이된 사고의 출처는 참고 사례 `03. 회로분석_TDSCU/log/` T6 · T7 · T9 · T10 의 구현요약·검증요약 — 줄마다 붙였다.

## 1. 두 단계 — 내가 어느 A 인가

| | 레이아웃 A (정의 3단계 · A1) | 출력 A (정의 6단계 · A2) |
|---|---|---|
| 하는 일 | 입력을 읽고 분석해, 무엇을 어떤 모양으로 만들지/바꿀지 **정한다** | 승인된 레이아웃대로 xlsx 를 **만든다(고친다)** |
| 산출 | 레이아웃 문서 `log/T{N}_<작업명>/설계명세.md` (md — D-59 G-1) + 구현요약 | `output/` 작업본 xlsx + 백업 + 수정 기록 파일 + 구현요약 |
| 쓰는 스킬 | `skills/레이아웃/<대상물>.md` | `skills/출력/<대상물>.md` |
| 하지 않는 것 | `output/` 에 xlsx 작업본·백업을 만들지 않는다. 입력은 **읽기만** 한다 | 레이아웃 결정을 스스로 바꾸지 않는다 (아래 §6) |

- 기존 파일 편집은 두 단계에 나뉜다 — **바꿀 내용의 결정은 레이아웃 A, 실제 적용은 출력 A** (D-59 확인 1 "가").
- 양식 채우기 · 신규 작성 · 기존 파일 편집의 차이는 스킬을 가르지 않고 **스킬 안의 적용 조건(출발점)** 으로 다룬다 (D-60 G-12). 출발점은 셋이다 — **바탕 있음·편집**(기존 xlsx 를 고친다) · **바탕 있음·양식**(정해진 양식의 칸을 채운다) · **바탕 없음**(근거 자료에서 새로 만든다).

## 2. 스킬 고르기 — 단계 × 대상물

- 스킬은 중첩형 `skills/<단계>/<대상물>.md` 다 (D-60 G-11 ⓐ). `레이아웃/` · `출력/` 은 묶음 폴더이고 스킬이 아니다 (`a/공통규칙.md` §7.2).
- **레이아웃 A** — 확정 사양이 정한 대상물의 레이아웃 스킬을 쓴다. 대상물이 둘이면 둘 다. 사양에 대상물이 없거나 둘로 읽히면 고르지 말고 레이아웃 문서의 열린 질문으로 올린다. 레이아웃 문서에는 쓸 스킬을 **스킬 경로 이름 그대로**(`레이아웃/표` · `출력/표` …) 적는다 — 이 이름으로 출력 A 와 검증자가 짝을 찾는다.
- **출력 A** — 승인된 레이아웃 문서가 정한 출력 스킬만 쓴다.
- 맞는 스킬이 없는 대상물(예: 차트)이면 비슷한 스킬로 메우지 않는다 — 멈추고 돌려준다 (새 대상물은 아래 §9).

## 3. 안전 — 원본 · 작업본 · 백업 · dry → apply (D-58)

- **원본·바탕·근거 자료는 고치지 않는다.** 착수할 때와 끝낼 때 입력 전부의 SHA-256 을 재서 구현요약에 적는다.
- **읽을 때는 사본을 읽는다** — 입력을 자기 세션 전용 임시 폴더(예: scratchpad 아래 `<담당>/`)로 복사해 사본만 연다. 사용자가 그 파일을 Excel 에 열어 두었어도 디스크 파일의 사본은 읽을 수 있다. 임시 폴더를 다른 A·B 와 함께 쓰지 않는다 — 남이 남긴 같은 이름의 파일을 덮어쓴 일이 있었다 (T6 A4 · A5).
- **작업본은 `output/` 에만** 만든다. 바탕이 있으면 바탕을 `output/` 으로 복사한 것에서 출발한다 — 바탕 경로의 파일을 열어 저장하지 않는다.
- **단계별 백업** — 작업본을 고치는 단계(apply 한 번)마다 편집 **직전에** `<작업본 이름>.pre<단계>.bak` 을 같은 폴더에 만들고 SHA-256 을 구현요약과 수정 기록 판본 절에 적는다. `<단계>` 는 판본과 차례로 짓는다 (예: `preR1`, 한 판에 여러 번이면 `preR1-2`). 같은 이름의 백업이 이미 있으면 **덮어쓰지 않고 멈춘다** (T6 A6_2차). 신규 작성 첫 판은 고칠 바탕이 없으므로 백업이 없다.
- **dry → apply 2단** — 쓰기 전에 바뀔 것의 목록(시트 · 셀/도형 · 전 값 · 후 값)을 먼저 뽑아 남기고(dry), 그다음 쓴다(apply). apply 뒤 실제로 바뀐 것을 다시 뽑아 dry 목록과 대보고, 다른 것은 이유를 적는다.
  - **dry 목록을 남기는 자리** — 작업본과 같은 폴더(`output/T{N}_<작업명>/`, 사양이 다른 경로를 정했으면 그 경로)의 md 파일 `<작업본 이름>_dry_<단계>.md` 다. apply 한 번에 파일 하나이고, `<단계>` 는 그 apply 의 백업 이름과 같은 조각이다 (`R1` · `R1-2` — 백업이 없는 신규 작성 첫 판도 `R1`). 목록의 "전 값"은 apply 직전 작업본의 값이다(신규 작성 첫 판이면 `(없음)`) — 수정 기록의 "원래 값"(원본)과 다르다. apply 전에 쓰고(백업을 뜨는 판이면 백업보다 먼저), apply 뒤에는 고치지 않는다. 같은 이름의 파일이 이미 있으면 백업과 같이 덮어쓰지 않고 멈춘다. 세션 전용 임시 폴더에는 두지 않는다 — 세션이 끝나면 사라진다.
  - **구현요약에 싣는 것** — dry 목록 파일마다 경로와 SHA-256 · 줄 수 · apply 뒤 실제 변경 수 · 목록과 다른 줄과 그 까닭. 목록 자체는 구현요약에 옮겨 싣지 않는다.
- **작업본 이름은 하나**로 유지한다. `_v2` · `_최종` · `_수정본` 같은 사본을 늘리지 않는다 — 판본은 백업과 수정 기록 판본 절로 구별한다. 이름·Rev·날짜가 같은 다른 판이 섞인 일이 있어 지문으로만 갈렸다 (T10 · T6 판본 혼재).

## 4. 착수 전 확인 — 사용자 환경에 손대지 않는다 (D-58)

착수할 때와 **apply 직전에 다시** 아래를 본다. 확인 결과(시각 · 값)를 구현요약에 적는다. 그 사이 사용자가 파일을 열 수 있다 (T6 A7 — 확인 뒤 잠금 파일이 새로 생김).

1. **잠금** — 작업본·입력 폴더에 `~$<파일명>` 이 있으면 그 파일은 누군가 Excel 로 열고 있다. 그 파일에 쓰지 않는다.
2. **실행 중 Excel** — `tasklist /FI "IMAGENAME eq EXCEL.EXE"` 로 PID 를 적어 둔다. 이 PID 들은 사용자의 것으로 보고 붙지도 닫지도 않는다.
3. **판본** — 작업본(있으면)의 SHA-256 이 직전 기록(수정 기록의 마지막 판본 절 · 승인 기록)과 같은지. 다르면 누가 저장한 것이다 — 사본끼리 비교해 무엇이 바뀌었는지 적고, 내용이 바뀌었으면 멈춘다 (T6 A5 · A6).

**멈추는 자리** — 아래에 걸리면 그 호출을 거기서 끝내고 상황을 돌려준다. 사용자 메시지만 보고 새 호출 없이 이어 가지 않는다 (T6 A5 "절차 밖" 지적).
- 쓸 파일에 잠금이 있거나 사용자 Excel 에 열려 있다 — 닫아 달라고 돌려준다. 다른 이름으로 저장하거나 강제로 덮어쓰지 않는다 (T10 R2).
- **권한 거부** — 실행 권한 판정이 쓰기·삭제를 거부했다. 다른 경로·다른 도구·조각 실행·설정 변경으로 같은 쓰기를 이뤄 내지 않는다. 돌려줄 때 사용자가 고를 수 있는 길(권한 설정 변경 · 사용자가 직접 실행 · Excel 을 닫은 뒤 닫힌 파일 방식)을 적는다 (T6 A2 · A4).
- 열린 통합문서가 저장되지 않은 상태(`Saved=False`)다 · 작업본 지문이 예상과 다르게 바뀌었다.

## 5. 도구 고르기 (D-58)

| 바탕·작업본의 특성 | 쓰기 도구 | 까닭 |
|---|---|---|
| 도형 · 댓글(메모·스레드 댓글) · 그림 · 데이터 유효성 · 서식 있는 글(한 칸 안 여러 글꼴) 가운데 하나라도 있다 | **Excel COM (pywin32)** | openpyxl 로 다시 저장하면 이런 요소가 빠지거나 바뀐다 (T10 A1_R1 M-1 · T6 A6) |
| 위 요소가 없는 단순 표 · 바탕 없는 신규 작성 | **openpyxl** | Excel 을 띄우지 않아 사용자 환경과 부딪히지 않는다 (T7 · T9) |

- 특성은 **레이아웃 A 가 입력에서 조사해** 레이아웃 문서에 도구와 함께 적는다. 출력 A 는 그 도구를 쓴다. 다른 도구로 바꿔야 하면 바꾸기 전에 멈춰 돌려준다.
- openpyxl 은 어느 경우든 **읽기·대조**에 쓸 수 있다. 조사법은 `참고자료/엑셀_도구와_함정.md` §1.
- 위 두 도구 밖의 도구(zip/XML 직접 편집 · Excel MCP 등)로 **쓰는 것**은 레이아웃 문서가 까닭과 함께 정한 경우에만 한다.
- Python 은 **`py`** 로 실행한다 (이 PC 의 `python` 은 스토어 바로가기다). 스크립트가 `__pycache__` 를 남기지 않게 `PYTHONDONTWRITEBYTECODE=1` 로 돌리거나, 남은 것을 지운다 (T10 A1_R2).
- **COM 을 쓸 때** — 새 인스턴스(`DispatchEx`)만 띄우고, 끝나면 **자기 인스턴스만** `Quit` 한다. 실행 전후 EXCEL.EXE 목록을 적어 "내가 띄운 것은 남지 않았다"를 확인한다. 한 번에 하나, 앞에서(foreground) 돌린다 — 여러 벌을 겹쳐 돌렸다가 인스턴스가 남은 일이 있었다 (T6 A6). 자세한 요령은 `참고자료/엑셀_도구와_함정.md` §2.

## 6. 레이아웃과 출력 사이

- **레이아웃 A** — 출력 A 가 추측 없이 따를 만큼 정한다: 무엇을(시트·셀/범위·도형) · 어떻게(전 → 후, 또는 만들 값의 규칙) · 왜(근거). 정하지 못한 것은 정한 척하지 말고 열린 질문으로 남긴다. 쓰는 꼴은 `참고자료/레이아웃_문서_양식.md`.
- **레이아웃 A — 사양 밖 결정** — 사양·사용자 요구에 없는 변경을 더해야 한다고 보면, 결정에 넣지 말고 M-N 으로 적은 뒤 열린 질문으로 올린다.
- **출력 A — 착수 전** 승인된 레이아웃의 지문을 다시 잰다 (정의 §승인된 레이아웃의 지문). 다르면 만들지 않는다.
- **출력 A — 레이아웃이 정하지 않은 세부**(열 너비 미세 조정 · 도형 좌표 미세 조정 · 글꼴 크기 등)는 정해서 M-N 으로 남긴다. **결과물의 내용·구조를 바꾸는 이탈**(시트·열·행 구성 · 값 · 블록·연결)은 하지 않고 멈춰 돌려준다 (정의 §되돌아갈 때).

## 7. 수정 기록 — 바뀐 셀 색 표시 + 기록 파일 (D-58 · D-59 G-2~G-6 · D-60 G-10 · D-61 G-14 · D-70)

출력 A 가 남긴다. 꼴은 `참고자료/수정기록_양식.md`.

- **색 표시** — 값을 바꾼 셀을 표시 색 하나로 칠한다. 색은 레이아웃 문서가 정한다 (바탕에 이미 쓰인 채움색과 다른 색). 병합 셀은 왼쪽 위 칸에 칠한다. 도형은 칠하지 않고 **기록 파일에만** 적는다 (G-5).
- **기록 파일** — 해당 Task 의 output 안, 작업본과 **별도 파일** (G-3). **한 파일 안에 판본(R)별 절** (G-6). 이전 판본 절은 지우거나 고치지 않는다.
- **판본 절에 싣는 것** — **그 판에서 새로 바뀐 셀(도형)만** (G-10). "원래 값" 칸은 **원본(바탕) 셀 값**이다 (G-2). 도형 표의 "전" 칸도 같다 — 원본(바탕)에서 그 도형 속성의 값이다. 원본 대비 누적은 판본 절을 합쳐 셀(도형)마다 마지막 기록으로 읽힌다.
- **한 줄의 단위** — 원래 값이 있던 칸은 **셀 하나에 한 줄**. 새로 채운 칸 · 새 행 · 새 열은 **범위 한 줄**로 묶어도 된다 (G-14).
- **바탕 없음(신규 작성)** — 첫 판(R1)은 색 표시·기록 파일을 하지 않는다. R2 부터 한다 (G-4). 이때 **원본은 R1 판으로 고정한다** — R3 이후에도 "원래 값" 칸(도형 표는 "전" 칸)은 R1 판 값이고, 색 표시도 R1 판 대비 누적이다 (D-70 · G-2). R1 판은 R2 의 첫 백업(`<작업본 이름>.preR2.bak`)으로 남으므로 원래 값은 그 파일에서 읽는다. 작업은 직전 판(지금 작업본)에서 이어 하고, 백업도 그 판에서 뜬다 (§3).
- 기록의 근거 칸에는 자료(파일·절·쪽·행) · 사용자 결정(일자와 사용자 말) · 레이아웃 결정 번호를 적는다. **검증 보고서 번호나 파이프라인 낱말(★ · B2 R1 X-1 같은 것)은 근거로 적지 않는다** — 사용자 결정으로 바꿔 적는다 (T10 B2_R2 X-2).

## 8. 사용자 취향 파일 — 레이아웃 A 가 읽는다 (D-62 · D-64)

- 레이아웃 A 는 레이아웃 문서를 쓰기 전에 `b/갈래별/엑셀작업/참고자료/사용자_취향.md` 를 **읽는다** (읽기만 — `b/` 아래는 검증자 영역). 자기 Task 의 대상물·대상에 걸리는 줄만 본다. 같은 대상의 줄이 여럿이면 가장 나중 줄을 본다 — 다만 §4 의 `B 소견` 줄끼리 갈린 것은 나중 줄이 앞 줄을 대신하지 않는다 (그 파일 §2-4). 갈린 줄을 모두 보고, 어느 쪽을 참고했는지(또는 어느 쪽도 따르지 않았는지)를 M-N 으로 적는다.
- 그 파일은 두 섹션이다 — **§3 사용자가 직접 요청한 것** / **§4 B 의 추론.** 둘을 다르게 다룬다:
  - **§3 의 줄** — 사용자의 말이다. 서식·표기·말투 결정에 **따른다.** 따르지 못하는 줄이 있으면 까닭과 함께 열린 질문으로 올린다.
  - **§4 의 줄** — B 가 미루어 안 것이거나 B 자신의 소견이다. **참고만 한다.** 따르기로 했으면 그 결정을 M-N 으로 적는다. §4 의 줄을 따른 결정을 "사용자가 요청한 것"이라 적지 않는다.
  - §3 과 §4 가 어긋나면 §3 을 따른다.
- 레이아웃 문서에는 **줄 번호로 가리킨다** (`§3 U2 를 따름` · `§4 B1 참고 — M-3`). 줄의 내용을 옮겨 적지 않는다.
- 사용자가 확정 사양에서 "이 취향을 지켜라"고 정한 줄은 사양이다 — 그 줄은 §3·§4 어디 있든 따른다.

## 9. 새 대상물 · 새 단계 — 열어 두는 자리 (D-59 "확장")

- **새 대상물** (예: 차트 · 피벗) — 이 갈래 `skills/레이아웃/<대상물>.md` · `skills/출력/<대상물>.md` 두 파일을 더한다. 이름은 검증자 쪽 `b/갈래별/엑셀작업/skills/` 의 짝과 **한 글자도 다르지 않게** 짓는다 (`a/공통규칙.md` §7.2). 이미 있는 스킬의 차례를 빌리면 그 스킬 경로 이름과 차례 번호를 밝힌다. 검증자 쪽 짝과 기준은 검증자가 쓰고 사용자가 승인한다 — A 쪽만 먼저 쓰지 않는다.
- **새 단계** (예: 레이아웃과 출력 사이 시범 출력) — `skills/<단계>/` 묶음 하나와 그 안의 대상물 스킬을 더한다. 단계는 정의 단계표와 함께 바뀌어야 하므로 **파이프라인신설 또는 개선 회차**로 다룬다.
- 실제 Task 에서 되풀이되는 방법이 새로 확인되면 이 규칙·스킬로 올릴 후보로 구현요약 "발견한 문제"에 적는다 — Task 도중에 고치지 않는다.

## 10. 받는 사람이 읽는 글 — 어휘 · 문장 · 말투 (D-61 G-17)

작업본에서 사람이 읽는 글 — 셀 문자열(머리 행 · 본문 · 안내 · 비고 · 질문 칸) · 시트 이름 · 메모 · 도형과 글상자의 글 · 설명 시트 — 을 쓸 때의 방침이다. 서식(글꼴 · 색 · 열 너비 …)은 레이아웃 결정과 §6 을 따르고, 여기서는 글만 다룬다.

- **누가 정하나** — 말투(한 파일 안에서 하나 — 예: "…다"로 맺는 문장 · "…함"으로 맺는 개조식 · 명사로 끝맺기)와 용어의 출처(근거 자료 · 바탕 · 용어집)는 **레이아웃 A** 가 레이아웃 문서 §6 의 결정(L-번호)으로 정한다. 바탕이 있으면 바탕에 이미 쓰인 말투와 용어를 먼저 따른다. 취향 파일 §3 의 줄이 걸리면 따른다 (§8).
- **출력 A** — 레이아웃이 글을 글자 그대로 정했으면 그대로 옮기고 고쳐 쓰지 않는다. 레이아웃이 값의 규칙만 정해 출력 A 가 글을 지어야 하면 아래 방침대로 짓는다. 레이아웃에 말투가 없으면 바탕의 말투를 따르고, 바탕도 없으면 정해서 M-N 으로 남긴다 (§6 — 레이아웃이 정하지 않은 세부). 무엇을 쓸지(글의 내용)가 정해지지 않았으면 짓지 않고 멈춘다 (§6 — 내용을 바꾸는 이탈).
- **어휘** — 받는 사람의 분야에서 쓰는 말(근거 자료 · 바탕 · 레이아웃이 정한 용어)을 그대로 쓴다. 한 파일 안에서 한 대상은 한 이름으로 부른다. 줄임말은 처음 나올 때 풀어 쓰거나 풀이 자리(`skills/레이아웃/표.md` ⑭)에 둔다.
- **문장** — 한 칸에는 한 가지 내용을 쓴다. 그 칸만 읽어도 무엇을 가리키는지 알게 쓴다 — 앞뒤 칸을 가리키는 말 대신 시트 · 셀 · 항목의 이름을 쓴다. 숫자에는 단위를 붙인다. 근거 자료에 없는 평가 · 강조 · 맺음 문장을 덧붙이지 않는다.
- **고르는 칸** — 상태 · 분류처럼 몇 낱말 가운데 하나를 고르는 칸은 레이아웃이 정한 낱말 목록 안에서만 쓴다.
- 내부 작업 기호와 내부 경로를 넣지 않는 것은 `skills/레이아웃/표.md` ⑭ · `skills/출력/표.md` ⑧ 그대로다.
