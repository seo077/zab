# 참고자료 — 레이아웃 문서 양식 (엑셀작업 갈래)

> 레이아웃 A 가 `log/T{N}_<작업명>/설계명세.md` 를 쓸 때의 꼴. 이 파일을 복사해 칸을 채운다. `▶` 줄은 설명이므로 채운 뒤 지운다.
> 설계 게이트 양식(`z/pipelines/_양식.md` — 배경 / 결정 / 흐름 / 스키마 / 리스크 / 만족 조건)을 엑셀 작업에 맞게 풀어 쓴 것이다. 어느 절이 그 여섯에 해당하는지는 절 제목 옆 괄호에 적었다.
> 대상물별로 결정 절(§6)에 더 적을 것은 그 레이아웃 스킬(`skills/레이아웃/<대상물>.md`)에 있다.

---

```markdown
# 레이아웃 — <작업명> (T{N})

| 항목 | 값 |
|---|---|
| 판본 | R<M> (작성 YYYY-MM-DD) |
| 작성 | 레이아웃 A (A1) |
| 근거 사양 | `log/AI 논의사항.md` <절 이름> |

## 1. 작업의 뼈대 (배경)
| 항목 | 값 |
|---|---|
| 대상물 · 스킬 | `레이아웃/<대상물>` → 출력 `출력/<대상물>` (대상물이 둘이면 줄을 더한다) |
| 출발점 | 바탕 있음·편집 / 바탕 있음·양식 / 바탕 없음 |
| 바탕 파일 | `input/…` (없으면 "없음") |
| 작업본 | `output/T{N}_<작업명>/<파일명>.xlsx` |
| 이번 판본 | R<M> |
| 한 줄 목적 | 이 작업본을 누가 무엇에 쓰나 |

## 2. 입력 고정
| # | 파일 (경로) | SHA-256 | 크기 (B) | 판을 가르는 표지 (같은 이름의 다른 판이 있을 수 있으면) |
|---|---|---|---|---|
▶ 원본·바탕·근거 자료 전부. 착수할 때 잰 값.

## 3. 읽은 범위
▶ 파일마다: 읽은 시트 · 범위. 아래 각각을 읽었는지 / 뺐는지 (뺐으면 까닭): 숨김 시트 · 숨김 행·열 · 자동 필터 · 병합 영역 · 그림·도형 속 글자 · 메모·스레드 댓글.

## 4. 입력 특성과 출력 도구 (스키마)
| 특성 | 있음/없음 · 개수 · 위치 | 어떻게 쟀나 |
|---|---|---|
| 도형 · 그림 · 차트 | | zip 부품 목록 (`xl/drawings/` · `xl/media/` · `xl/charts/`) |
| 메모 · 스레드 댓글 | | `xl/comments*` · `xl/threadedComments/` |
| 데이터 유효성 · 조건부 서식 | | 시트 XML `dataValidations` · `conditionalFormatting` |
| 수식 | | openpyxl (`data_only=False`) |
| 병합 · 인쇄 설정 · 정의된 이름 | | `mergeCells` · `pageSetup` · `definedNames` |
| 채움색 분포 | | 셀 채움 RGB 집계 |
- 출력 도구: COM (pywin32) / openpyxl — 까닭 (`a/갈래별/엑셀작업/규칙.md` §5)
- 실행: `py`

## 5. 분석 결과
▶ 개수 · 합계 · 목록 · 대조 결과. 값마다 근거 위치(파일 · 시트 · 셀/행 · 도형)를 붙인다. 셀 수 있는 것은 어떻게 셌는지(스크립트 · 조건)를 적어 다른 사람이 다시 셀 수 있게 한다.
▶ 값 해석이 갈리는 자리(수식 셀 · 날짜 일련번호 · 숫자처럼 보이는 글자 · 앞뒤 공백·줄바꿈 · 병합 셀 · 빈 문자열과 빈 칸)를 만났으면 어떻게 읽었는지 적는다 (`참고자료/엑셀_도구와_함정.md` §1).

## 6. 결정 (결정 · 흐름)
▶ 번호(L-1, L-2 …)를 붙인다 — 출력 A 와 수정 기록이 이 번호로 가리킨다.
| # | 무엇을 (시트 · 셀/범위 · 도형 이름/id) | 전 → 후 (또는 만들 값의 규칙) | 근거 (자료 절·쪽·행 · 사용자 결정) |
|---|---|---|---|
▶ 대상물별로 더 정할 것은 그 레이아웃 스킬(`skills/레이아웃/<대상물>.md`)의 "차례" 절에 있다.
▶ "적절히" · "보기 좋게" · "필요하면" 같은 말을 결정 칸에 쓰지 않는다 — 정하지 못했으면 §9 열린 질문으로.

## 7. 지킬 것 — 보존 목록 (바탕이 있을 때)
▶ 바꾸면 안 되는 것을 바탕에서 재서 개수·위치로 적는다: 시트 이름·순서·숨김 · 정의된 이름 · 수식 · 데이터 유효성 · 조건부 서식 · 병합 범위 · 인쇄 설정 · 그림·도형·차트·메모/댓글 · 사람이 기대는 원문 칸 (비워 둘 칸 포함).

## 8. 수정 기록 계획
| 항목 | 값 |
|---|---|
| 표시 색 (RGB) | `FF……` — 바탕에 쓰인 채움색: <목록> 과 다름 |
| 기록 파일 | `output/T{N}_<작업명>/<작업본 이름>_수정기록.md` |
| 이번 판본 절 | R<M> |
| 바탕 없음 첫 판 | "R1 색 표시·기록 미적용 (D-59 G-4)" — 해당할 때만 |

## 9. 열린 질문 (리스크)
| # | 무엇을 몰라서 | 무엇이 막히나 | A 의 안 (있으면 — 확정처럼 적지 않는다) |
|---|---|---|---|
▶ 입력에 없는 값 · 근거끼리 다른 값 · 사양 밖이라 사용자에게 물어야 할 변경. 확인할 수 없어 남긴 것은 까닭을 붙인다.

## 10. 사용자 취향 반영
▶ `b/갈래별/엑셀작업/참고자료/사용자_취향.md` 의 줄 번호로만 가리킨다 — 예: `§3 U2 따름 (결정 L-7)` · `§4 B1 참고 — M-3` · `§3 U4 못 따름 — 질문 Q-2`. 걸리는 줄이 없으면 "걸리는 줄 없음 (읽은 판 SHA-256 앞 8자리)".

## 11. 만족 조건 (만족 조건)
▶ 이 레이아웃이 실현되면 작업본에서 무엇을 보게 되나 — 결정 번호와 짝지어 적는다 (예: "L-3: `목록` 시트 37행, 열 A~M"). 산출물이 무엇을 담게 되는지만 적는다.

## 12. 변경 이력
| 판본 | 일자 | 고친 절 | 까닭 (사용자 결정 · 판정에서 나온 고칠 거리) |
|---|---|---|---|
```

- 레이아웃 R2 이후에는 이 문서를 고쳐 쓴다. 고친 절과 까닭을 §12 에 쌓는다 — 이전 결정이 흔적 없이 바뀌지 않게.
- ★ 설계 승인 뒤에는 이 문서를 고치지 않는다 (정의 §승인된 레이아웃의 지문).
