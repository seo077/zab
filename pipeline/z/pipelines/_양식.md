# 파이프라인 정의 — 양식

> 새 작업을 추가한다는 것 = **이 파일을 복사해 `<작업명>.md` 로 저장하고 칸을 채우는 것.** 그것 말고 할 일은 없다.
> 아래 `▶` 로 시작하는 줄은 설명이므로 채운 뒤 지운다.
>
> **이 정의를 한 판 돌리는 것 = Task 하나(`T{N}`)다.** 프로젝트 안에서 같은 정의를 여러 판, 다른 정의와 병렬로 돌릴 수 있다.
> 아래의 `log/T{N}_<작업명>/` 은 Z가 Task 개설 때 만드는 그 Task의 방이다 — 실제 번호 `N` 은 Z가 부여한다.
> 진행 중 같은 단계의 재작업은 **Task 내부 반복 `R{M}`** 이다 (예: `T1 / 3단계 R2`). 완료 뒤 변경은 완료 판을 보존하고 새 Task에서 변경 차이·보존할 바탕·영향을 정한다(`../부팅.md` §완료 뒤의 변경).

---

## 머리표

| 항목 | 내용 |
|---|---|
| 목적 | `<이 파이프라인이 무엇을 만들어내는가 — 한 줄>` |
| 입력 | `<시작할 때 있어야 하는 것. 파일·자료·사용자가 정해줘야 할 값>` |
| 출력 | `<끝났을 때 손에 남는 것. 파일 경로 수준으로 구체적으로>` |
| 쓰는 갈래 | `<a/갈래별/·b/갈래별/ 안의 폴더 이름. 예: ppt · 회로설계 · 엑셀>` |
| 예상 단계 수 | `<숫자>` |

▶ **쓰는 갈래**: 이 이름으로 A·B가 `a/갈래별/<갈래>/` · `b/갈래별/<갈래>/` 를 찾아 읽는다. 갈래 폴더가 아직 없으면 만들어야 한다.
▶ 갈래를 안 쓰는 순수 범용 작업이면 `없음` 이라고 적는다.

## 단계표

| # | 담당 | 하는 일 | 읽을 자료 | 쓸 곳 | 병렬 |
|---|---|---|---|---|---|
| 1 | `<Z/A/B>` | `<한 줄>` | `<경로>` | `<경로>` | `<단독 / A1·A2 동시>` |
| ★ | 사용자 | `<무엇을 확인·승인하는가>` | `<사람이 열어볼 파일 경로>` | — | — |
| 2 | | | | | |
| 3 | | | | | |
| 종합 | B(종합) | 각 B 보고서를 모아 최종 판정 한 줄 | `<B1·B2… 보고서 경로>` | `<최종 판정 파일 경로>` | 단독 |
| ★ | 사용자 | 최종 수락 여부 결정 | `<최종 판정 파일 경로>` | — | — |

### 각 칸 채우는 법

| 칸 | 채우는 법 |
|---|---|
| **#** | 순번. 사람 확인 지점은 번호 대신 **★** 를 쓴다 |
| **담당** | `Z`·`A`·`B`·`사용자` 중 하나. 여럿이면 `A1`·`A2` 처럼 번호를 붙인다 |
| **하는 일** | 한 줄로. 두 줄이 필요하면 그건 두 단계다 — 쪼갠다 |
| **읽을 자료** | 그 단계 담당이 **열어볼 파일 경로**. "필요하면 알아서" 는 쓰지 않는다. B 단계에서는 경로만 적고 내용 설명은 붙이지 않는다 |
| **쓸 곳** | 그 단계 담당이 **쓸 파일 경로**. 한 파일에 주인은 하나 — 두 단계가 같은 경로를 쓰면 잘못 짠 것이다 |
| **병렬** | `단독` 또는 동시에 도는 담당 목록. 갈라지는 게 깨끗하지 않으면 병렬로 두지 않는다 |

### ★ 표시 — 사람 확인 지점

**★ 가 붙은 줄 = 에이전트 호출을 둘로 끊는 자리다.**

- 앞 단계 에이전트는 **거기서 일을 끝낸다.** "확인받고 이어서 해라" 라고 시키지 않는다.
- 직접 확인 승인 또는 `../상호작용규칙.md` §6.4의 조건부 진행 권한을 Z가 기록한 뒤, **새 세션**으로 다음 단계를 시작한다. 구체 수정 범위와 다음 행동의 기존 권한을 확인하며 역할의 ★ 종료는 유지한다.
- 서브에이전트는 작업 도중 사용자와 대화할 수 없다. 그래서 ★ 는 두 모드 모두에서 **같은 자리**에 있어야 한다.

★ 를 찍어야 하는 자리의 신호:
- 사용자 승인이 있어야 다음이 성립하는 곳 (검증 기준 확정 · 설계 확정 · 최종 수락)
- 되돌리기 어려운 일이 시작되기 직전
- 갈림길이라 사람이 골라야 하는 곳

### 설계 게이트 — 선언한 파이프라인에만 있다

▶ 설계를 먼저 확정받아야 하는 작업이면 이 절을 남기고, 단계표에 아래 두 줄을 넣는다. 필요 없으면 이 절을 표째 지운다 — **선언이 없는 파이프라인은 설계 명세를 만들지 않는다** (전 파이프라인 강제가 아니다).

설계 게이트를 두려면, **단계표에 두 줄을 스스로 선언한다:**

| # | 담당 | 하는 일 | 읽을 자료 | 쓸 곳 | 병렬 |
|---|---|---|---|---|---|
| n | A | 설계 명세와 단계·회차 요약 작성 — 배경 / 결정 / 흐름 / 스키마 / 리스크 / 만족 조건 | `<사양·합의 문서 경로>` · `<B 작성·Z 배정 설계 전달면 경로/판(검증 진행 시)>` | `log/T{N}_<작업명>/설계명세.md` · `log/T{N}_<작업명>/구현요약/A<N>_설계_R<M>.md` · `<호출에서 지정한 제출 사본 경로>` | 단독 |
| ★ | 사용자 | 설계 승인 (게이트) | `log/T{N}_<작업명>/설계명세.md` | — | — |

- 설계 명세의 주인은 **A**, 자리는 **그 Task의 log 방** — `log/T{N}_<작업명>/설계명세.md`.
- 담는 것은 **그 Task 하나**의 설계 결정·구조다. 프로젝트 전체의 모습은 설계 명세가 아니라 프로젝트 루트의 `프로젝트지도.md`(Z 기록)가 담는다.
- ★설계 승인은 다른 ★와 똑같이 역할 호출을 끝낸다. 진행 권한과 새 세션 배치는 위 ★ 절 및 `../상호작용규칙.md` §6.4를 따른다.
- 검증 진행 판은 최초·수정 회차 모두 기준 개정·승인 뒤 설계를 배정한다. 내용이 의존하면 파일이 달라도 병렬로 두지 않는다. B가 작성한 발췌/대상별 기준 또는 원문 전재의 승인 판·조건·외부 정의를 전달하고 A에게 B 전체 본문을 배정하지 않는다(`../상호작용규칙.md` A-10).
- 설계·기준의 매 제출/승인 판 원문은 소유 역할이 복구 가능한 사본으로 남긴다. 사양이 Git/버전 저장을 택하면 실제 복원을 확인한다. 기준 r과 호출 R, 작업본과 고정 사본, 소유 역할 제출과 Z의 승인 연결은 구별한다(`../상호작용규칙.md` §6.1).
- 단계·회차 요약 이름은 `A<N>_<단계명>_R<M>.md`다. 실제 쓸 경로를 단계표와 호출에 함께 적는다. 예시 경로는 권한을 자동 추가하지 않는다.

### 병렬 배치 시 파일 소유

▶ 같은 단계를 여럿이 동시에 도는 경우에만 채운다. 없으면 표째 지운다.

| 담당 | 맡은 범위 | 전용으로 쓰는 파일 |
|---|---|---|
| `<A1>` | `<맡은 몫>` | `<이 담당만 쓰는 경로>` |
| `<A2>` | `<맡은 몫>` | `<이 담당만 쓰는 경로>` |

- 공동 장부(`log/manifest.json` — Task 장부)는 **Z만 쓴다.** 병렬 담당들은 읽기만 한다.
- 요약은 담당별 파일로 나눈다 (`log/T{N}_<작업명>/구현요약/A1_*.md`).

### 판정 종합 단계

▶ B가 **여럿일 때만** 둔다. B가 한 명이면 종합 줄을 지운다.

- 여러 B의 결과를 **Z가 합치지 않는다.** 합치는 순간 Z가 판정한 것이 되기 때문.
- **종합 B** 를 한 명 더 두고, 각 B 보고서의 **경로만** 넘긴다.
- 종합 B의 최종 판정 한 줄이 이 파이프라인의 판정이다.

## 완료 조건

▶ "다 됐다"를 무엇으로 확인하는지 적는다. 열어보면 참·거짓이 갈리는 형태로 쓴다.

- [ ] `<출력 파일이 전부 있고 비어 있지 않다 — 경로 나열>`
- [ ] `<★ 지점의 사용자 승인이 모두 기록에 남았다>`
- [ ] `<최종 판정이 나왔고 사용자가 수락했다>`
- [ ] `<log/manifest.json 의 해당 Task(T{N}) 상태가 갱신됐고 history 에 각 단계가 한 줄씩 남았다>`

### 판·배정 연결 기록

| 무엇 | 어디에 | 누가 |
|---|---|---|
| 제출 판 원문·자기 관찰·지문 | `log/T{N}_<작업명>/관찰/<역할>_<단계명>_R<M>/제출본/` 및 제출 기록 (실제 경로는 호출에서 고정) | 해당 소유 A/B |
| 회차별 중립 권한·변경 배정·승인 연결 | `log/T{N}_<작업명>/배정/` | Z |
| 실제 호출 전문 | `log/T{N}_<작업명>/호출/<역할>_<단계명>_R<M>.md` | Z |

중립 배정은 당시 실제 읽기/쓰기·제외 범위와 호출의 동일 권한 구획·지문을 고정한다. 판정 B의 판독/대체 출처와 전후 비교 자료는 `../상호작용규칙.md` §6.2대로 배정한다. 현재 장부나 A 변경목록만으로 대체하지 않는다.
