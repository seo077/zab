# 파이프라인 정의 — 엑셀작업

> 엑셀(xlsx) 작업 전반을 Task 하나로 처리하는 파이프라인이다. **실제 작업 두 단계**로 이뤄진다 — ① 레이아웃 작업(입력 읽기·분석 + 무엇을 어떤 모양으로 만들지/바꿀지 결정 → 레이아웃 문서) ② 출력 작업(레이아웃 기반으로 실제 xlsx 작성). 단계마다 구현자·검증자가 따로 있고, 대상물(현재 표·블록도)별 스킬을 `skills/` 에서 끌어와 쓴다. 새 대상물·새 작업 형태가 **추후 추가될 수 있다.**
> **상태: 완료 (파이프라인신설 — 01. 최초부팅 및 디버깅 T6, ★ 최종 수락 2026-10-15).** 1단계(Z)에서 머리표를, 3단계(A)에서 단계표·완료 조건·남길 기록을 채웠다 — 근거는 확정 사양 `01. 최초부팅 및 디버깅/log/AI 논의사항.md` Round 7 D-58 ~ D-72.
>
> `T{N}` · `<작업명>` · `<대상물>` 은 변수다 — Z가 Task를 개설할 때 채운다. `<대상물>` 은 스킬 경로 이름의 뒷부분(`표` · `블록도` …)이다.

> **담당 표기** — A1 = 레이아웃 A, A2 = 출력 A. B1 = 레이아웃 기준 B, B2 = 레이아웃 B, B3 = 출력 기준 B, B4 = 출력 B, B5 = 취향 기록 B. **B 다섯은 서로 별도 fresh 세션**이다 — 기준을 쓴 눈과 판정하는 눈을 나누고, 두 단계의 판정도 나눈다. A1·A2 도 별도 세션이다 (사이에 ★ 가 있다).
> **판정 종합 단계는 두지 않는다** (D-61 G-17). B2·B4 의 판정은 각자 다른 ★(설계 승인 · 최종 수락)의 재료다. 표현(AI스럽지 않은 어휘)·디자인·가독성 확인은 B4 가 함께 한다.
> **번호** — 건너뛴 행이 있어도 번호를 당기지 않는다. 어느 판에서든 "6단계" 는 A2 출력이라, 장부·실행로그의 단계 표기가 판마다 달라지지 않는다.
> **스킬** — `<대상물>` 은 Task 마다 하나 이상이다 (표와 블록도를 함께 다루면 둘 다). 레이아웃 스킬은 확정 사양에서 고르고 레이아웃 문서가 확정하며, 출력 스킬은 **승인된 레이아웃 문서가 정한 대상물**대로 고른다. A 쪽 스킬과 B 쪽 스킬은 스킬 경로 이름(`레이아웃/표` · `레이아웃/블록도` · `출력/표` · `출력/블록도`)으로 짝지어진다 (`a/공통규칙.md` §7.2 · `b/공통규칙.md` §9.2).

### 사양 — 1단계 협의에서 정하는 것 (★ 사양 확정의 대상)

1. **대상물** — 이번 Task 가 다루는 대상물(`표` · `블록도` …)과 그에 맞는 레이아웃 스킬. 정하지 못했으면 정하지 못했다고 적는다 (B1 이 추정해서 고르지 않는다).
2. **출발점** — 바탕 파일을 고치는가(기존 파일 편집) · 정해진 양식을 채우는가(양식 채우기) · 바탕 없이 새로 만드는가(신규 작성).
3. **입력** — 원본·바탕 xlsx 와 근거 자료의 경로 (`input/` 아래).
4. **산출 경로** — 기본 `output/T{N}_<작업명>/`. 다르게 하려면 여기서 정한다.
5. **요구** — 무엇을 만들거나 바꾸는지, 하지 말 것, 사용자가 이 Task 에서 지키라고 정한 취향(있으면).

### 설계 게이트 — 이 파이프라인은 선언한다

레이아웃 작업이 곧 설계다 (D-59 "사람 확인"). 단계표의 **3 (A1 레이아웃 문서) · ★ 설계(레이아웃) 승인** 두 줄이 `_양식.md` 의 설계 게이트 두 줄이다.

- 설계 명세의 주인은 **A1**, 자리는 그 Task 의 log 방 — `log/T{N}_<작업명>/설계명세.md`. 이 파이프라인에서는 그 파일을 **레이아웃 문서**라 부른다.
- 레이아웃 문서가 담는 것은 그 Task 하나의 결정이다. 쓰는 꼴은 `a/갈래별/엑셀작업/참고자료/레이아웃_문서_양식.md` 에 있다.
- ★ 설계 승인 뒤에는 레이아웃 문서가 **출력 단계의 사양**이 된다. 승인 뒤에는 그 파일을 고치지 않는다 — 고칠 일이 생기면 아래 §되돌아갈 때.

### 출력 기준 승인 — Task 마다 고른다 (D-62 G-18 · D-63 G-20)

| 때 | 누가 | 무엇을 | 남는 것 |
|---|---|---|---|
| ★ 레이아웃 기준 승인 자리 | Z 가 묻고 사용자가 정한다 | "출력 기준(`검증기준_출력.md`)도 사람이 승인할지 / 생략할지" | 장부(`log/manifest.json`) 그 확인지점에 사용자 답 원문 |
| 5단계 끝 (B3 결과를 받았을 때) | Z | 아래 셋 가운데 하나로 ★ 출력 기준 승인을 **켜거나 끈다** | 장부 history 한 줄 |

- **켠다** — ① 사용자가 "받는다"고 정했다 ② 사용자가 "생략"이라 정했어도 **B3 가 사람이 정할 회색지대를 올렸다**(합본을 멈춘 경우 포함 — G-20) ③ 장부에 선택 기록이 없다 (기록 없이는 생략으로 보지 않는다).
- **끈다** — 사용자가 "생략"이라 정했고, B3 가 사람이 정할 회색지대를 올리지 않았다. 이때 6단계(A2)로 바로 간다. **생략 판에서는 장부에 남은 그 생략 결정이 B4 가 기준을 쓰는 근거다** — 생략은 "사람이 기준을 보지 않아도 된다"는 결정이지, 사람이 정할 일을 B 가 대신 정해도 된다는 결정이 아니다.
- 어느 쪽이든 ★ 의 자리는 정해져 있으므로 모드1·모드2 에서 같은 자리에서 멈춘다.

공통 조건부 진행(`../상호작용규칙.md` §6.4)은 구체 수정 범위와 다음 행동을 이미 허용한 회차의 권한이다. 위 출력 기준 승인 생략의 사용자 선택·회색지대·기록 유무 조건을 넓히거나 회색지대 재개방을 없애지 않는다. 직접 확인 승인·이 정의의 생략 결정·조건부 진행 기록은 구별한다. 역할은 해당 단계에서 종료하고 다음은 새 세션이다.

### 승인된 레이아웃의 지문

- A1은 매 레이아웃 제출 판을 호출에 지정된 별도 사본으로 고정하고 bytes·SHA256·제출 시각·바탕 판·단계/역할/회차 R·문서 리비전과 경로를 남긴다. Z는 그 사본에 승인 원문·출처·날짜·범위를 별도 연결한다. 기준 판은 B가 보존하며 기준 r과 호출 R은 구별한다. 사본이 기본이며 사양이 선택한 Git/버전 저장은 파일·commit/blob·복원 위치와 실제 복원 열람을 확인한다. 지문만 남기는 것으로 원문 보존을 대신하지 않는다(`../상호작용규칙.md` §6.1).
- ★ 설계(레이아웃) 승인 때 Z 는 승인 대상 `log/T{N}_<작업명>/설계명세.md` 의 **SHA-256** 을 재서 장부 그 확인지점에 사용자 말과 함께 적는다. 이것이 "승인된 레이아웃"을 가리키는 값이다.
- 그 값이 B2 보고서에 적힌 값과 다르면(판정 뒤에 고친 판을 승인한 경우) Z 는 그 사실을 같은 확인지점에 함께 적는다.
- 6단계 호출문은 이 값을 싣는다. A2 는 착수할 때 `설계명세.md` 를 다시 재어 같은지 확인하고, 다르면 **만들지 않고 멈춘다.** A2 는 이 값을 구현요약과 수정 기록 파일의 판본 절 머리에 적는다.

### 되돌아갈 때 (회차)

- 새 회차를 시작해도 앞 제출/승인 원문 사본과 판/승인 연결은 유지한다. A 요약은 `A<N>_<단계명>_R<M>.md`로 단계·회차를 구별하고 기존 과거 파일 이름은 바꾸지 않는다. 실제 사본·요약 쓸 곳은 호출에 명시한다.
- **레이아웃 R{M}** — B2 판정이나 ★ 설계 승인에서 고칠 거리가 나오면 3단계(A1) → 4단계(B2, 새 fresh 세션)를 R2·R3 … 으로 다시 돈다. 레이아웃 기준은 다시 쓰지 않는다 (기준을 바꿀 일이 생기면 B1 새 리비전 + ★ 다시 승인).
- **출력 R{M}** — B4 판정이나 ★ 최종 수락에서 고칠 거리가 나오면 6단계(A2) → 7단계(B4, 새 fresh 세션)를 다시 돈다. 승인된 레이아웃은 그대로다.
- **출력 중 레이아웃 결함** — A2 가 승인된 레이아웃만으로는 만들 수 없거나 레이아웃을 바꿔야 하는 자리를 만나면, 바꾸지 않고 멈춰 돌려준다 (`a/공통규칙.md` §8). 사용자가 레이아웃 R{M} 으로 되돌리기로 정하면 3단계부터 다시 돌고, 새로 승인된 레이아웃으로 5단계(B3)부터 다시 간다 — 승인 지문이 바뀌기 때문이다.

완료 뒤 새 변경은 완료 판을 보존하고 새 Task의 변경 차이·보존 바탕·영향을 사양으로 정한다(`../부팅.md` §완료 뒤의 변경). 외부 장애의 진행 단계 재개와 구별한다.

### 취향 기록 — 8단계 (D-62 · D-63 G-21 · D-64 G-22)

- ★ 최종 수락 뒤 Z 가 B5 를 **늘 한 번** 부른다. 쌓을 것이 있는지 가리는 것도 B5 의 몫이다 — 쌓을 것이 없으면 B5 는 줄을 더하지 않고 그 사실을 결과로 돌려준다.
- B5 가 쓰는 곳은 **파이프라인 저장소의 원본** `b/갈래별/엑셀작업/참고자료/사용자_취향.md` 하나다 (작업 도중이 아니라 ★ 최종 수락 뒤이므로 — D-63). 그 파일 밖의 파이프라인 저장소는 B5 에게도 읽기 전용이다. 무엇을 어떻게 적는지는 그 파일 §1 · §2 를 따른다.
- 8단계는 판정이 아니므로 ★ 최종 수락의 결과를 바꾸지 않는다. 다만 Task 를 마감하는 것은 8단계 결과를 받은 뒤다 (완료 조건).

### 협업의 뼈대

- **기준 먼저** — 레이아웃·출력 각 단계의 기준(B1·B3)이 그 단계의 A 보다 앞에 있다 (D-61 G-16). 순서를 바꾸지 않는다.
- **A 에겐 넉넉히, B 에겐 아껴서** — 호출 메시지 규칙은 `z/상호작용규칙.md` §2·§3 그대로. 6단계 호출문에는 승인된 레이아웃 지문을 싣는다.
- **판정은 B2·B4 · 수락은 사용자 · Z 는 안 만들고 안 판정** — 금지선 그대로.
