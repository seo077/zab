### 형식·연결·판 전환 인계

1단계의 `넷리스트형식.md`는 한 담당이 쓴다. 실제 원문/바이트 표본, 공백·탭·빈 선두/말미 필드·부품 값 경계, 패키지/핀 수, exporter 판·순서 출처, 자리↔핀 대응 근거·불확실성을 남긴다. 방법과 필드는 `a/갈래별/회로분석/참고자료/06.넷리스트와_신호연결.md`를 따른다. 기준점 몇 개나 핀 수의 일치를 전체 핀맵 확정으로 쓰지 않는다.

2~3단계는 신호망과 전원/수동망을 구분하고, 배정 신호의 양 끝·분기 전체에 소자/핀·원문 위치·DS 판/페이지·가능 기능·선택 모드·활성 조건·의도 출처를 연결한다. TX/RX 이름은 보조 식별자다. 핀/모드 불명은 Q-ID·영향·대체 확인을 남기며 깊이/제출 단계별 허용 미확정은 해당 Task 사양에서 정한다. 기존 L1/L2/L3를 모두 전수 분석으로 바꾸지 않는다.

입력·파서·핀맵이 달라진 연결과 이전 미확인 연결은 다시 추적한다. 재사용 연결에는 전후 입력 판/지문·양 끝/분기·모드 불변 근거·이전 확인 출처를 남긴다. 노드 번호 존재만으로 승계하지 않으며 검증된 불변 연결의 매회 수작업 전수 분석을 강제하지 않는다.

4단계 준비 → ★ 시뮬 결과 회수의 사용자 수동 실행 → 5단계 연결 → B 대조/판정 순서를 유지한다. Z는 B에게 준비 사양과 결과 양쪽의 경로·판을 배정한다. 미확인 후속은 항목·영향·시도/대체 수단·필요 결정으로 중계하고 담당·회차·중단/수락은 Z·사용자가 정한다. Q-ID/후속표 등록은 현재 필요한 확인을 대신하지 않는다.

★의 역할 종료·직접 확인 승인/조건부 진행 구별은 `../상호작용규칙.md` §1.1·§6.4를 따른다. 조건부 진행으로 사용자 질의 응답이나 수동 시뮬 결과를 생성한 것으로 취급하지 않는다.

### 병렬 배치 시 파일 소유

> step 3·step B 는 모듈·축이 많으면 여럿이 동시에 돌 수 있다. 그때만 아래를 채운다. 한 파이프라인 안에서 병렬을 안 쓰면 이 표는 지운다.

| 담당 | 맡은 범위 | 전용으로 쓰는 파일 |
|---|---|---|
| `A1` | 배정받은 모듈 묶음 (예: 전원·클록 계열) | `output/분석/회로분석_<프로젝트명>_<그 모듈들>.md` |
| `A2` | 다른 모듈 묶음 (예: 통신·IO 계열) | `output/분석/회로분석_<프로젝트명>_<그 모듈들>.md` |

- 공동 장부(`log/manifest.json` — Task 장부)는 **Z만 쓴다.** 병렬 담당들은 읽기만 한다.
- 요약은 담당별 파일로 나눈다 (`log/T{N}_회로분석/구현요약/A1_*.md`).
- 데이터시트 색인(`회로분석_<프로젝트명>_데이터시트색인.md`)처럼 **여럿이 함께 채워야 하는 한 파일**은 병렬로 두지 않는다 — 한 담당(예: A1)이 모아 쓰고 나머지는 자기 몫을 넘긴다.

### 판정 종합

> B가 모듈·축별로 여럿일 때만 종합 줄을 둔다. B가 한 명이면 위 단계표의 `B` 줄 하나로 끝나고 이 절은 지운다.
