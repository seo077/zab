## Claude MCP

In each project's config, command is the installed Claude executable, args is mcp serve, and cwd is the actual absolute path of the project. Expose only Agent/TaskStop, and use 30 seconds for startup, 1,800 seconds for tools and default_tools_approval_mode=auto. cwd is not an OS security boundary. Use the existing account and model, and do not install a new key or program.

When the user requests delegation to Claude, or Claude is selected in mode 2, pass an independent call message to a new Agent. Ordinary roles use general-purpose·description·prompt; if there is an actual selection under interaction-rules §1.3.1, check model/effort against the current Agent schema and pass them, and omit name/isolation. If isError, the internal status/content and toolStats are present, check those values and the actual returned ID. TaskStop targets only the ID returned while your own call is actually running. Do not presume a stop in progress from an agentId returned after completed, a name set by the caller, a JSON-RPC request number or a Codex cell ID. Querying the connection list, and calling the model, stopping and cleaning up the server, are different observations.

The project's check-claude-mcp.mjs diagnoses stdio directly with the Node standard library. The default is connection/list, and --call-agent and --stop-probe are explicit choices. Also observe separately the connected Agent of the actual Codex app/CLI. Do not substitute the Node result for confirmation of the app connection. The stop diagnostic is not an ordinary A/B role and requests a wait of at most 20 seconds only. The current Agent schema has no general local background argument, so do not add an arbitrary argument or switch to remote isolation. The R2 helper requests TaskStop(task_id=agentId) only when the Agent response contains both status=running, while it is running, and the actual agentId. If the ID is disclosed only after completed, it does not send TaskStop and leaves exit 3 and stop-unobserved. Record each of the TaskStop request/response, the Agent's final state and the server cleanup. If the final state cannot be queried again with only the permitted Agent/TaskStop, the stop is unconfirmed. Do not fill in as success a value for which there is no original error or response.
