# Improvement history

The place to leave **why · how** the pipeline repository was fixed.

## What to leave

Leave only lessons whose usefulness has been confirmed through repetition. Something experienced once stays in the project-side log; **when it is experienced twice**, promote it here.
The direction of promotion is one way only — project → pipeline. Nothing is sent back down the other way.

## When to write

**Do not write during** the work. During the work, everything under `pipeline/` is read-only.
Hold what you discover during the work as a note, and organize it here in a separate round after the work is finished.

## File name

```
NNN_<one-line title>.md      e.g. 001_subagent-skipped-user-approval.md
```

## What one entry holds

| Item | Content |
|---|---|
| Date | When it was experienced |
| Where | Which project · which pipeline · which step |
| What happened | Facts only. Briefly |
| Why it happened | If it is a guess, write that it is a guess |
| What was fixed | What in which file, and how |
| If it happens again | What to look at if the same thing occurs again |
