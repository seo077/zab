# 검증기준 — 갈래 "회로분석"

> **이 문서는 세 층 가운데 둘째 층이다** (`b/검증기준_공통.md` §8). 여기 있는 것은 **회로분석 작업에서만** 본다.
> 실제 작업에서는 `공통` + 이 문서 + 이번 Task에만 필요한 항목을 검증자가 하나로 합쳐 해당 Task 방의 `log/T{N}_<작업명>/검증기준.md` 로 내려보낸다.
> **판정 값·심각도·종합 규칙의 정의는 여기 없다** — `b/검증기준_공통.md` §1·§2·§6 에만 있다. 여기서는 무엇을 볼지(항목)만 정한다.
> 본문은 검증자만 쓴다. 다른 역할은 폴더와 빈 파일까지만.

## 0. 이 문서가 보는 것과 안 보는 것

**보는 것** — 회로분석 파이프라인이 실제 회로에 굴러갔을 때 나오는 **분석 보고서**(출력 4계층)가 갈래가 요구하는 형태·내용·정합을 갖췄는가.

**안 보는 것**
- 파이프라인 정의 파일(`z/pipelines/회로분석.md`)·규칙(`a/갈래별/회로분석/`) 자체의 형식 → 공통층 + 이번 작업 항목이 본다. 이 문서는 **산출된 분석 보고서**를 대상으로 한다.
- 회로 설계가 옳은지에 대한 **B의 독자 공학 판정** → B는 보고서가 **자기 근거로 결론에 닿는가**를 보지, 회로를 대신 재설계하지 않는다. 회로 사실(넷리스트·데이터시트 값)의 대조는 P-4 사실 검증으로 하되(§4), 최종 설계 옳고 그름은 사용자·시뮬 몫.

> 이 갈래는 **원본을 건드리는 작업이 아니다**(입력을 변환·이동하지 않고 새 분석을 낸다). 따라서 공통 §5(무손상·비교 기준·보존 목록)는 원칙적으로 걸리지 않는다 — 단 **입력 판본 고정**(§1의 첫 ★)은 예외로 이 문서 CA-2 가 따로 본다.

### 뼈대

```
§1  입력·판본        CA-1 ~ CA-3   — 무엇을 근거로 분석했나, 그 판본이 고정됐나
§2  출력 4계층       CA-4 ~ CA-8   — 네 계층이 다 있고 각자 제 일을 하나
§3  모듈 분해·깊이    CA-9 ~ CA-11  — M#_코드 명명 · L1~L3 깊이 배정
§4  분석의 실질       CA-12 ~ CA-18 — 3자 교차 · 4축 · 데이터시트 대조 · 정량 동작점
    §4.1 연결 근거    CA-26 ~ CA-30 — 형식 · 방향/이름 · 양 끝 · 판 전환
    §4.2 판독 출처와 수단 — 합본에 옮길 연결·시뮬 판독 방법

§6  사람 확인 3자리    CA-23 ~ CA-25 — ★ 입력판본 · 질의응답 · 시뮬대조 반영
§7  회색지대·발굴     — 이 갈래 특유의 조심할 자리
```

## 1. 입력·판본 (CA-1 ~ CA-3)

| # | 항목 | 심각도 | 어떻게 보나 |
|---|---|---|---|
| **CA-1** | 기본 3종 입력을 **모두 근거로 썼다** | 필수 | 보고서가 회로도(PDF)·netlist·BOM **셋 다**를 실제로 참조했는지. 셋 중 하나라도 근거로 안 나타나면 3자 교차(CA-12)가 성립할 수 없다. 선택 추가 입력(요구사항·인터페이스 사양서·블록도)이 있었다면 그것도 어디에 반영됐는지 본다 |
| **CA-2** | 분석의 근거가 된 **입력 판본이 고정·명시**됐다 | 필수 | 첫 ★(입력 판본 확정)에서 고른 3종의 판본(크기·시각 등 지문)이 보고서에 적혀 있고, 이후 분석이 **그 판본을 기준**으로 갔는지. 판본이 안 박히면 어느 도면을 본 분석인지 되짚을 수 없다 |
| **CA-3** | 근거 입력과 결론 사이가 **끊기지 않는다** | 권장 | 결론·오류 지적이 "어느 입력의 어디"에서 나왔는지 되짚을 수 있는지(핀·넷·부품 참조 등). 근거 없이 단정한 곳이 있으면 지적으로 남긴다 |

## 2. 출력 4계층 (CA-4 ~ CA-8)

> 출력 = **통합 분석 · 모듈별 분석 · 설계오류목록 · 데이터시트 색인** 네 계층(머리표). 넷은 서로 다른 일을 하며, 서로 가리켜야 한 벌이 된다.

| # | 항목 | 심각도 | 어떻게 보나 |
|---|---|---|---|
| **CA-4** | **네 계층이 다 있고 비어 있지 않다** | 필수 | 통합·모듈별·설계오류목록·데이터시트 색인 각각의 산출물(파일 또는 절)이 존재하고 알맹이가 있는지. 파일 경로 수준의 구체화는 A가 정의 step 3에서 정하므로, **정의 완료 조건에 나열된 경로**와 실제 산출을 대본다 |
| **CA-5** | **통합 분석**이 전체를 꿰는가 | 필수 | 모듈별을 그냥 이어붙인 것이 아니라, 회로 전체의 기능·신호 흐름·모듈 간 관계를 한 층 위에서 정리하는지. 모듈별의 복사면 미달 |
| **CA-6** | **모듈별 분석**이 모듈마다 실제 내용을 담는가 | 필수 | §3에서 나눈 모듈(M#) 각각에 대해 기능·동작 분석이 있는지. 배정된 깊이(L1~L3, CA-11)에 맞는 상세를 갖췄는지 |
| **CA-7** | **설계오류목록**이 진단 결과를 담는가 | 필수 | 목적이 "오류·위험·개선점 진단"이므로, 발견한 오류·위험·개선점이 목록으로 정리됐는지. 각 항목이 근거(어느 모듈·어느 입력)와 이어지는지. **없으면 "없음을 확인했다"가 근거와 함께 적혔는지** — 조용한 공란은 미달 |
| **CA-8** | **데이터시트 색인**이 대조를 뒷받침하는가 | 권장 | BOM 부품별로 참조한 데이터시트가 색인돼 있고, 4축 분석의 데이터시트 대조(CA-14)와 이어지는지 |

## 3. 모듈 분해·깊이 (CA-9 ~ CA-11)

| # | 항목 | 심각도 | 어떻게 보나 |
|---|---|---|---|
| **CA-9** | 회로가 **모듈로 분해**됐다 | 필수 | 회로 전체를 통째로 보지 않고 기능 단위 모듈로 나눴는지. 나눈 결과가 회로의 실제 구성과 어긋나지 않는지(넷리스트·도면 대조) |
| **CA-10** | 모듈 명명이 **일관된 코드 체계**를 따른다 | 권장 | 모듈에 `M#_기능코드` 꼴의 식별자가 붙고, 그 식별자가 통합·모듈별·오류목록 전반에서 같은 것을 가리키는지. 같은 모듈을 두 이름으로 부르면 상호참조가 깨진다 |
| **CA-11** | 모듈마다 **분석 깊이가 배정**됐다 | 권장 | 모듈별로 L1/L2/L3 같은 깊이 등급이 매겨졌고, 실제 분석 상세가 그 등급과 맞는지(깊게 볼 모듈을 얕게 훑고 넘어가지 않았는지). 깊이 배정 근거가 자의적이지 않은지 |

## 4. 분석의 실질 (CA-12 ~ CA-18)

> 형식만 보면 **모양은 4계층인데 실제로는 분석이 없는** 보고서를 통과시킨다(공통 C-F1 일관). 아래로 실질을 본다. 여기가 이 갈래의 핵심이다.

| # | 항목 | 심각도 | 어떻게 보나 |
|---|---|---|---|
| **CA-12** | **3자 교차검증**을 실제로 했다 | 필수 | 넷리스트↔도면↔BOM 셋을 서로 대본 흔적이 있는지 — 셋이 어긋나는 곳(도면에 있는데 BOM에 없는 부품 등)을 짚었는지. 한 소스만 옮겨 적었으면 교차가 아니다 |
| **CA-13** | **네 축을 다 밟았다** | 필수 | ①데이터시트 대조 ②질의응답 의도 반영 ③논리정합성(의도↔회로↔데이터시트) ④정량 동작점 — 네 축이 분석에 실제로 나타나는지. 빠진 축이 있으면 어느 축인지 지적 |
| **CA-14** | **데이터시트 대조**가 BOM 기준으로 됐고, 실패를 삼키지 않았다 | 필수 | 부품 스펙을 데이터시트로 확인했는지, 그 기준이 BOM인지. **못 구한 데이터시트는 "보류 + Q-ID"로 드러냈는지** — 못 구한 것을 확인한 것처럼 넘어갔으면 미달(공통 §7 "확인 불가를 통과로 세지 않는다" 일관) |
| **CA-15** | **논리정합성**이 세 꼭짓점을 잇는다 | 필수 | 설계 의도 ↔ 실제 회로 ↔ 데이터시트 세 가지가 서로 맞는지를 따졌는지. 셋 중 둘만 보고(예: 회로만, 의도 없이) 정합성을 논했으면 반쪽이다 |
| **CA-16** | **정량 동작점**이 수치로 나온다 | 권장 | 전압·전류·타이밍 등 동작점이 말이 아니라 수치·근거식으로 제시됐는지. "정상 동작할 것으로 보임" 같은 정성 서술만 있으면 CA-13 ④축 미충족으로 본다 |
| **CA-17** | **오류·가설이 사실에서 도출**됐다 | 필수 | 설계오류목록·가설(H-N)이 앞의 대조·분석에서 나온 것인지, 아니면 근거 없이 얹힌 것인지. 각 오류가 "어느 모듈·어느 근거"로 되짚어지는지 |
| **CA-18** | 만든 쪽의 **자평을 근거로 삼지 않는다** | 필수 | "분석 완료" "이상 없음" 같은 산출자 서술은 근거가 아니다(공통 §7 일관). 보고서 **본문의 분석 자체**로 판단한다. 이 항목은 검증자 자신에 대한 규율이다 |

### 4.1 넷리스트와 신호 연결 (CA-26 ~ CA-30)

기존 번호 CA-1~25는 유지한다. 아래는 3자 교차·논리정합성을 실제 핀 연결까지 따라가기 위한 추가 항목이다. 분석 대상 신호·깊이·제출 단계와 **허용 미확정 범위는 해당 Task 사양에서 정하고 합본에 고정**한다. L1/L2/L3를 무조건 전수 확정으로 바꾸지 않는다. 승인 범위에 필요한 사실을 확인할 수 없으면 §7과 공통 §7을 따른다. 사양이 빠졌다는 이유로 B가 임의로 범위를 줄이거나 추정으로 빈칸을 메우지 않는다.

| # | 항목 | 심각도 | 어떻게 보나 |
|---|---|---|---|
| **CA-26** | **실제 넷리스트 형식·핀맵의 근거와 불확실성이 기록됐다** | 필수 | `output/분석/넷리스트형식.md`와 실제 입력 판을 대조한다. 공백·탭·연속 공백·빈 선두/말미 필드·부품 값 경계, 패키지·핀 수·내보내기 도구/판·순서 출처, 원문 표본과 자리↔핀/볼 대응 근거를 찾는다. 빈 필드를 버리지 않고 실제 형식에 맞게 재현한다. 핀 수 일치나 기준점 3개만으로 전체 핀맵을 확정하지 않으며 문자열 정렬을 모든 도구의 규칙으로 삼지 않는다. 확인 범위와 가설/미확정을 분리한다 |
| **CA-27** | **핀 기능과 방향을 전체 연결·모드·활성 조건에서 대조했다** | 필수 | 전원/수동망과 신호망을 구별한다. 배정 신호의 양 끝과 모든 분기·외부 구동을 따라가며 데이터시트 기능·다중화 기능·선택 모드·활성 조건을 실제 결선과 맞댄다. 양방향·오픈드레인·3상태를 구분한다. 출력 0개/복수는 조건별 확인 후보이지 자동 오류나 정상 결론이 아니다. 선택 모드·구동 조건이 불명하면 미확정으로 남긴다 |
| **CA-28** | **신호 이름을 방향·연결·의도의 확정 근거로 쓰지 않았다** | 필수 | TX/RX 등 보조 이름이 어느 장치 기준인지와 별개로 핀 기능·실제 연결·사용자 의도 출처를 대조한다. 이름과 핀 기능이 어긋나도 이름으로 방향을 덮지 않는다. 이름만 있는 설명은 기능 대조의 증거가 아니다 |
| **CA-29** | **배정 신호의 양 끝 소자·핀/볼에서 원문과 기능 근거까지 추적된다** | 필수 | 모듈의 신호 연결 표에서 모든 끝점/분기의 소자·핀/볼, 입력 판·넷리스트 원 행/필드 및 도면/BOM 위치, 데이터시트 판·페이지/표·핀 기능 근거를 따라간다. 소자명만 있는 끝점은 완결된 핀 근거가 아니다. 핀 미확정은 Q-ID 등으로 대상·영향·대체 확인을 남기며, 사양의 깊이/제출 단계별 허용 범위와 대조한다. 기록했다는 이유만으로 필요한 핀 확인을 충족 처리하지 않는다 |
| **CA-30** | **판 전환 시 재추적과 불변 연결 재사용의 근거가 구분됐다** | 필수 | 입력·파서·핀맵 변경의 영향 연결과 이전 미검증 연결을 다시 추적했는지 본다. 재사용 연결은 전후 입력 판·지문, 양 끝 소자/핀·분기 연결의 불변 근거, 모드/활성 조건의 불변 또는 변화 영향, 이전 직접 확인 출처를 연결한다. 노드 번호 존재만으로 보존을 입증하지 않는다. 근거가 있는 불변 연결까지 매회 수작업 전수 확인하도록 강제하지 않는다. 최초 판으로 승계/재사용 대상이 없으면 합본에 해당 없음과 이유를 남기고 집계에서 제외한다 |

### 4.2 판독 출처와 수단 — 합본에 함께 싣는다

기준 B는 아래 방법과 해당 Task의 실제 경로·판·읽기 범위를 합본의 판독 방법 구획에 옮긴다. 이 절의 방법은 새 항목이나 별도 심각도를 만들지 않는다. 판정 B는 승인 합본의 항목과 방법을 쓰며, A가 만든 파서/점검 코드의 출력만으로 판정하지 않는다. 출처가 배정되지 않았으면 공통 §8.2에 따라 Z에게 요청한다.

| 대상 | 주 출처 | 대체 출처·조건 | B의 판독 수단 |
|---|---|---|---|
| 형식·핀/볼 매핑 | 고정한 넷리스트 원문·넷리스트형식 기록, 해당 CAD/exporter의 핀 순서 근거·부품 라이브러리/패키지 핀표 | 같은 판의 원문 사본, 내보내기 명세·핀명이 포함된 별도 내보내기와 원 입력의 대응. 일부 기준점 정합은 그 범위의 보조 증거 | 원 행을 바이트·탭/공백 구분으로 읽고 알려진 표본과 재현한다. 선두/말미 빈 자리·값 경계 표본을 포함하고 핀 수/전체 순서의 확인 수준을 별도로 적는다 |
| 연결·기능·의도 | netlist·도면·BOM, 데이터시트 핀 기능/다중화 표, 실제 선택 모드·활성 조건, 사용자 DQ 응답 | 같은 판의 명시적 핀 연결 내보내기, 도면 이미지 판독, 추가 원문 자료. 각 대체의 대응·한계와 실제 읽기 권한 필요 | 노드가 나타나는 모든 부품 행과 분기를 직접 찾아 소자/핀으로 연결하고 기능/모드를 대조한다. 한쪽 행만 읽거나 이름으로 핀을 채우지 않는다 |
| 판 전환 | 전후 입력·파서/핀맵 판과 변경 기록, 이전 확인 출처 | 동일 판 사본과 불변 연결의 대응 기록 | 변경/이전 미확인 연결은 재추적한다. 재사용은 전후 양 끝·분기·모드 불변 증거를 확인하고 그 범위만 사용한다 |
| 시뮬 준비·결과 | `output/모델/<모듈명>_시뮬사양.md`, 실제 모델/가정, `output/시뮬/`의 회차·항목별 파형·로그/결과, 모듈 H-N·Q-ID | 동일 판 사본, 관찰점·축·단위·판 연결이 있는 파형 이미지/텍스트. 값 또는 조건을 판독할 수 없으면 미확인 | 준비 사양 판과 사용자 실행 결과 판을 연결하고 기대 동작점·자극·해석 설정·관찰 노드·모델 가정을 직접 읽어 결과와 대조한다 |

PDF 평문 추출 실패만으로 모든 대체 판독이 불가능하다고 결론내리지 않는다. 배정·도구 범위 안에서 이미지 등 가능한 수단을 검토하고 실패/미실시 이유를 남긴다. 확인 불가이면 §7의 영향·대체 수단·필요 결정으로 인계하며 다른 출처의 신호 이름이나 이전 보고서를 원문 기능 증거로 올리지 않는다.

## 5. 추적 가능성 (CA-19 ~ CA-22)

> 이 갈래는 여러 단계에 걸쳐 **미해결 항목을 ID로 넘긴다**(설계논리질의 DQ · 보류 Q · 가설 H). ID가 끊기면 나중 단계가 앞 단계의 무엇에 답한 것인지 알 수 없다.

| # | 항목 | 심각도 | 어떻게 보나 |
|---|---|---|---|
| **CA-19** | **설계논리질의(DQ-ID)** 가 초안 단계에서 산출됐다 | 필수 | 설계논리질의는 미리 받은 입력이 아니라 **분석 초안 중 파이프라인이 만들어 사용자에게 물은** 것이다(사양 D-31 (1)). 그 질의 리스트가 DQ-ID로 붙어 존재하는지 |
| **CA-20** | **질의응답이 심층 분석에 반영**됐다 | 필수 | 사용자가 답한 설계 의도가 이후 축별 심층 분석(②의도 반영·③논리정합성)에 실제로 들어갔는지. 답을 받아만 두고 분석이 안 바뀌었으면 ★가 헛돈 것 |
| **CA-21** | **보류(Q-ID)** 가 걸린 채 끝나지 않았거나, 끝났으면 그 사실과 영향이 드러난다 | 권장 | 데이터시트·핀맵·선택 모드 등 미해결 Q-ID의 대상·영향·대체 확인을 드러내고 필요한 결정을 인계했는지 본다. 열린 항목을 닫힌 척하지 않는다. 이 권장 항목은 보류 기록의 추적성이다. 별도 필수 사실의 미확인은 Q-ID/후속표 등록으로 해소되지 않으며 공통 §7대로 처리한다 |
| **CA-22** | **가설(H-N)** 이 확정 결론과 구분된다 | 권장 | 아직 검증 안 된 가설과 확정된 오류가 뒤섞이지 않았는지. 가설이 시뮬 대조(★)로 넘어가는 대상임이 드러나는지 |

## 6. 사람 확인 3자리 (CA-23 ~ CA-25)

> 얼개의 ★ 세 곳 — 입력 판본 확정 · 질의 응답 · 시뮬 대조. 각 ★에서 사람이 준 것이 **실제로 반영**됐고 **기록에 남았는지**를 본다(★ 자리 자체를 어디 두는지는 정의·Z 몫이라 이 문서가 정하지 않는다 — 반영 여부만 본다).

| # | 항목 | 심각도 | 어떻게 보나 |
|---|---|---|---|
| **CA-23** | ★① **입력 판본 확정**이 반영됐다 | 필수 | CA-2 와 짝. 사용자가 고정한 판본이 분석의 기준으로 쓰였고 그 승인이 기록에 남았는지 |
| **CA-24** | ★② **질의 응답**이 반영됐다 | 필수 | CA-20 과 짝. 사용자 응답과 (열렸다면) 선택 추가 입력이 심층 분석에 들어갔고, 응답 사실이 기록에 남았는지 |
| **CA-25** | **시뮬 결과 회수·대조**가 준비 사양과 연결됐다 | 필수 | 기존 4단계에서 A가 작성한 `output/모델/<모듈명>_시뮬사양.md`의 기대 동작점·자극·해석 설정·관찰 노드·모델/Q-ID와 H-N을 직접 읽는다. 사용자가 같은 사양 판으로 수동 실행해 `output/시뮬/`에 넘긴 회차/항목별 결과·파형·로그를 연결하고 B가 대조한다. 보고서의 사용자 확인 오류와 미판정 잔여 가설을 구분하며 B의 H-N 판정은 근거를 갖춰 남긴다. A의 자평이나 결과 파일만으로 준비 사양을 대신하지 않는다. 시뮬 미수행·판 불일치·결과 판독 불가는 영향과 필요 결정을 남기고 공통 §7을 따른다 |

시뮬 준비는 기존 4단계의 일이며 새 단계를 만들거나 `output/모델/`을 제거하지 않는다. Z는 사용자 결과 회수 뒤 판정 B에게 모델/준비 사양과 시뮬 결과 **양쪽**의 실제 경로·판을 배정한다. 실행은 사용자, 준비는 A, 대조·판정은 B의 역할이다. 불일치는 분석·모델·설정/자극을 구분해 근거를 확인하며, B가 모델이나 산출물을 직접 고치지 않는다. 다음 담당·회차는 Z·사용자에게 돌린다.

## 7. 회색지대·자체 발굴 — 이 갈래에서 특히 조심할 자리

| 상황 | 어떻게 |
|---|---|
| 데이터시트를 못 구해 스펙 확인이 안 된다 | CA-14의 보류 표기는 확인 여부를 숨기지 않는 요구다. 현재 승인 기준의 필수 사실을 확인하지 못했다면 Q-ID 등록 여부와 무관하게 미달이다(공통 §7). 권장 사실이면 영향에 따라 조건부/미달로 처리한다. 확인한 척하면 CA-14도 미충족이다 |
| 회로 자체가 옳은지 B가 자신 없다 | B는 회로를 재설계하지 않는다. **보고서가 자기 근거로 결론에 닿는가**만 본다. 공학적 옳고 그름의 최종은 시뮬·사용자 몫 (§0) |
| 시뮬 결과가 아직 없다(시뮬 결과 회수 미수행) | 가설 H-N의 확정 여부를 단정하지 않는다. 준비 사양·결과의 미확인과 영향을 남긴다. 현재 승인 범위에서 필요한 필수 대조를 한계 기록만으로 충족 처리하지 않는다(CA-25·공통 §7) |
| 핀/볼 매핑 또는 선택 모드가 미확정이다 | Q-ID와 영향 연결·대체 수단·필요 결정을 남긴다. 데이터시트의 핀 기능 확인과 exporter 자리 매핑/실제 사용 모드 확인을 분리한다. 확인 수준을 섞어 항상 충돌·반드시 부유로 단정하지 않는다 |
| 출력이 0개 또는 여러 개다 | 망 종류·전체 분기·외부 구동·양방향/오픈드레인/3상태와 활성 조건을 확인할 후보로 둔다. 출력 개수만으로 설계 정오를 확정하지 않는다 |
| 미확인을 후속표에 올렸다 | 후속 등록과 현재 판정을 구분한다. B는 확인 불가 항목·영향·대체 수단·필요 결정까지만 제시한다. 담당·회차·중단/수락은 Z·사용자 결정이며 현재 필수 미확인은 그대로 남는다 |
| 모듈을 어디까지 쪼갤지 정답이 없다 | 분해 자체보다 **분해가 회로 사실과 어긋나지 않는가**(CA-9)와 **깊이 배정이 자의적이지 않은가**(CA-11)로 본다 |
| 첫 판이라 얕게 한 바퀴만 돌았다 | 사양이 첫 판을 가볍게 돌린다고 정했으므로(D-31, Phase 4=구동 시험), 깊이 부족 자체는 즉시 미달이 아니다. 단 **4계층·4축·3자 교차라는 뼈대가 서 있는가**는 첫 판에도 필수다. 얕은 것과 빠진 것을 구분한다 |

> **자체 발굴(X-N)은 판정 회차에서** 붙인다. 이 문서는 기준 작성 단계이므로, 위는 판정 시 조심할 자리를 미리 표시해 둔 것이다.

## 8. 근거 — 이 항목들을 어디서 뽑았나

기존 CA-1~25의 출처는 **`AI 논의사항.md` Round 1 §"Phase 4-1 회로분석 파이프라인 입력 시드 사양 확정 (D-31)" §확정 사양(머리표 + 얼개)** 다. 아래 보강은 원 작업 공간 T8의 D-98 확정사양 R1(H-001·U-01~06, 채택 조정점 포함)에서 도출했다. T8 입력의 과거 회로 사실·파서 가설을 새 회로 판정으로 승계한 것이 아니다. 각 실제 회로 Task는 이 갈래와 자기 사양을 합본·승인하여 쓴다(공통 §8 · 독립성 I-1).

| 자리 | 근거 |
|---|---|
| §1 입력·판본 (CA-1~3) | 머리표 "입력" + 얼개 첫 ★(입력 판본 확정) + 교훈 C(판본 지문) |
| §2 출력 4계층 (CA-4~8) | 머리표 "출력 = 4계층" + 얼개 5단계(4계층 상호참조) + 자산 7 |
| §3 모듈·깊이 (CA-9~11) | 얼개 1단계(M#_기능코드 · L1/L2/L3) + 자산 2·3 |
| §4 분석의 실질 (CA-12~18) | 얼개 2·3·4단계(3자 교차 · 4축 · 데이터시트 실패=보류 · 정량 동작점) + 자산 1·4·5 |
| §5 추적 가능성 (CA-19~22) | D-31 (1)(설계논리질의는 산출물) + 얼개 2단계 DQ-ID · 3단계 Q-ID · 4단계 H-N |
| §6 ★ 3자리 (CA-23~25) | D-31 (3) ★ 3곳 + 얼개 ★ 세 줄 |
| §4.1 CA-26~30·§4.2 | T8 확정사양 R1 U-01~05, 추가 조정 X-9. 실제 형식·양 끝·조건·판 전환의 근거와 한계 |
| CA-21·§7 보강 | T8 U-06. 공통 필수 미확인 규칙과 후속 결정의 역할 경계 |
| CA-25·§4.2 시뮬 보강 | T8 H-001, 추가 조정 X-5. 기존 4단계 준비물부터 사용자·B 읽기까지 연결 |
