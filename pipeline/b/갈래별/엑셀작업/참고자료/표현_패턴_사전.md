## 2. 제외 사유 — 패턴에 걸려도 지적하지 않는 경우

건마다 **어느 사유인지** 적는다. 사유를 못 적으면 제외하지 않는다.

| 사유 | 예 |
|---|---|
| 근거 자료 원문을 그대로 옮긴 인용 | 데이터시트 핀 이름 · 넷 이름 · 규격서 문장 · 사용자 답 원문 칸 |
| 고유명 | 부품·표준·제품·기관 이름 |
| 대체어가 뜻을 바꾼다 | 신호가 실제로 "거쳐 간다"는 사실을 말하는 `~를 통해` |
| 사용자가 그 표기를 정했다 | 사양·사용자 답에 그 표기를 쓰라고 한 기록이 있음 (위치를 적는다) |
| [바탕] 원래 있던 글 | 이번 Task 가 바꾸지 않은 칸·도형 — 보존 대상(OC-8). 메모로만 |

**"어색하지 않다" · "이 정도는 괜찮다"는 제외 사유가 아니다** (TDSCU T6 §9).

## 3. 규칙으로 잡히는 글 오류 (OC-22 ④)

명백해서 규칙으로 가려지는 것만 센다. 띄어쓰기·문체의 판단이 갈리는 것은 세지 않는다.

| 오류 | 잡는 법 |
|---|---|
| 같은 낱말이 잇달아 두 번 (`의 의`, `을 을`) | 공백으로 나눈 토큰의 연속 중복 |
| 문장부호 겹침 (`..` · `,,` · `。` 섞임) | 문자열 검색 (말줄임 `…`·`...` 은 제외) |
| 괄호·따옴표 짝이 안 맞음 | 칸·도형 단위로 여는/닫는 수 비교 |
| 조사 겹침 (`을를` · `은는` · `이가`) | 문자열 검색 |
| 같은 파일 안에서 같은 낱말의 표기가 갈림 (`데이타`/`데이터`) | 표기 후보 쌍을 뽑아 둘 다 쓰였는지 — 용어집이 있으면 Task 셋째 층 "용어 통일"로 넘긴다 |
