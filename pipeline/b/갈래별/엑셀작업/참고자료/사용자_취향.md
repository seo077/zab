# 참고자료 — 사용자 취향 누적 (엑셀작업 갈래)

> **판정 근거가 아니다.** 여기 쌓이는 것은 엑셀 산출물의 표현·디자인·가독성에 대한 좋다·싫다의 기록이다. **두 섹션으로 나뉜다** — **§3 사용자가 직접 요청한 것**(사용자 말 원문) / **§4 B 의 추론**(B 가 사용자의 말·결정·반응에서 미루어 안 사용자 취향 + 출력 B 자신의 취향 소견). 항목·심각도는 `검증기준.md` 에만 있다 — 이 파일의 줄은 그 자체로 통과·미달을 가르지 않는다 (`b/공통규칙.md` I-5 — 판정 근거는 승인된 기준 · 산출물 · B 의 판단 셋뿐).
> **§3 과 §4 는 무게가 다르다.** §3 은 사용자의 것이고, §4 는 B 의 것이다 — §4 의 줄을 사용자가 요청한 것으로 옮겨 쓰지 않는다.
> **통째로 읽지 않아도 되게** 대상별로 줄을 쌓는다 (`b/공통규칙.md` §9 참고자료 규약). 읽는 쪽은 자기 Task 의 대상물·대상에 걸리는 줄만 본다.
> 이 파일을 두게 된 근거: 원 작업 공간의 `log/AI 논의사항.md` Round 7 **D-62** — "B의 취향 소견(좋다·싫다)은 판정에 넣지 않고 사용자 취향 누적 파일에 쌓는다 — 자리는 `b/갈래별/엑셀작업/참고자료/` 안" · 사용자 말 "사용자마다 다르기 때문에 사용자의 취향을 누적해서 적을 수 있는 파일이 있으면 좋겠네요. 싫다 뿐만 아니라 좋다까지. 너무나 주관적인 부분이기 때문". 누가 · 언제 쓰나는 **D-63 G-21 (ㄴ)** — 사용자 말 "G-21 : ㄴ, B가 파악한 사용자 취향도 적기 가능". 무엇을 어디에 나눠 적나는 **D-64 G-22 (ㄴ)** — 사용자 말 "1. ㄴ, 사용자가 직접 요청한 내용과 B의 추론 같은 파일 내 섹션 나눠서 분리해서 적어주세요".

## 1. 누가 어떻게 쓰나

| 누구 | 무엇을 | 근거 |
|---|---|---|
| **레이아웃 A** | 레이아웃 문서를 쓰기 전에 **읽는다** — 사용자 취향을 레이아웃 결정(서식·표기·말투)에 참고한다. **§3(사용자 요청)과 §4(B 의 추론)를 가려 읽는다** — §4 의 줄을 따랐을 때 그것을 사용자가 요청한 것이라고 적지 않는다. 어느 줄을 따랐는지·따르지 않았는지, 두 섹션에 어떤 무게를 두는지는 A 쪽 규칙이 정한다 | D-62 "레이아웃 A 읽음" · D-64 G-22 (ㄴ) 섹션 분리 |
| **출력 B** | **참고만 한다.** 판정에 쓰지 않고, **이 파일에 쓰지 않는다.** B 자신의 취향 소견(좋다·싫다)은 보고서의 X-N 메모 "취향 소견" 묶음에 적고(소견마다 X-N 번호), 이 파일에 같은 대상의 줄이 있으면 그 섹션·번호를 함께 적는다(같은 방향인가 · 어긋나는가) — 사용자가 ★ 최종 수락 때 한눈에 보도록. 그 소견은 뒤에 취향 기록 B 가 §4 로 옮긴다 | D-62 "출력 B 참고만" · D-64 G-22 (ㄴ) · `검증기준.md` §5.1.7 머리말 |
| **취향 기록 B** (기록하는 사람) | **★ 최종 수락 뒤 짧은 B 호출 하나**가 이 파일에 줄을 더한다 — 아래 §2 의 차례대로. 판정하지 않는 호출이고, 이 파일 밖에는 쓰지 않는다. **이 파일 본문을 쓰는 것은 이 B 뿐이다** (`b/공통규칙.md` §1.1 — `b/` 아래 본문은 검증자만). Z 는 호출만 하고 줄을 쓰지 않는다 | **D-63 G-21 (ㄴ)** |
| 그 밖 | 출력 기준 B 는 사용자가 그 Task 사양에서 "이 취향을 지켜라"고 정한 경우에만 그 줄을 셋째 층 항목으로 옮긴다 (`검증기준.md` §6 "사용자 취향의 Task 반영"). 그 밖의 경우 어떤 B 도 이 파일의 줄로 판정하지 않는다. §4 의 줄은 사용자가 그 Task 에서 지키라고 정하지 않는 한 셋째 층 항목이 되지 않는다 | `b/검증기준_공통.md` §8 (승인된 기준만 판정 근거) |

> **쓰는 때와 읽기 전용 규칙** — `b/부팅.md` 세 가지 금지 3 · `b/공통규칙.md` §1 · `README.md` 는 "작업 도중 `pipeline/` 아래는 읽기 전용"이라 한다. 취향 기록 B 가 쓰는 때는 **★ 최종 수락 뒤 — 작업 도중이 아니다.** 이 쓰기는 사용자 결정 D-63 G-21 (ㄴ) 이 정한 자리다 (`b/공통규칙.md` I-6 끝 줄 — 사용자 최종 결정이 기준). 이 파일 밖의 `pipeline/` 은 그 B 에게도 읽기 전용이다.

## 2. 무엇을 적나 — 취향 기록 B 의 차례

**읽는 것** (호출이 경로를 준다): 그 Task 의 장부 확인지점(`log/manifest.json` — `사용자_말`) · 그 Task 의 논의 기록(있으면) · 출력 B 보고서의 X-N "취향 소견" 묶음 · 이 파일.

1. **§3 — 사용자가 직접 요청한 것.** 장부 확인지점 등에 남은 사용자 말 가운데 엑셀 산출물의 표현·디자인·가독성에 대한 좋다·싫다를 **원문 그대로** 옮긴다. 요약·해석은 "대상" 칸에만 짧게. 사용자가 실제로 말한 것만 이 섹션에 들어간다 — B 가 미룬 것은 아무리 확실해 보여도 §4 로 간다.
2. **§4 — B 의 추론.** 두 바탕의 줄을 같은 섹션에 적고, "바탕" 칸으로 가린다.
   - `사용자 반응` — 사용자가 좋다·싫다고 직접 말하지 않았어도 **사용자의 말·결정·반응에서** 미루어 알 수 있는 사용자의 취향 (D-63 "B가 파악한 사용자 취향도 적기 가능"). 예: 출력 B 의 취향 소견을 보고 사용자가 아무 말 없이 그 자리를 고쳐 달라고 했다 · 같은 종류의 수정 요청이 되풀이됐다.
   - `B 소견` — 출력 B 가 보고서 X-N "취향 소견" 묶음에 적은 **B 자신의** 좋다·싫다 (사용자가 반응하지 않은 것 포함 — D-64 G-22 (ㄴ)). 소견을 한 줄씩 옮기고, 사용자가 그 소견에 보인 반응이 있으면 "근거" 칸에 함께 적는다. 취향 기록 B 자신이 그 Task 산출물을 다시 열어 새 소견을 만들지는 않는다 — 옮기는 것은 출력 B 보고서에 이미 적힌 소견뿐이다.
   - **"근거" 칸에 어디서 무엇을 보고 적었나**(확인지점 이름 · 보고서 경로와 X-N 번호 · 사용자 말 인용)를 적는다 — 근거를 댈 수 없으면 적지 않는다.
   - 사용자가 B 소견에 **말로** 답했으면(예: "그 색은 싫다") 그 말은 §3 줄이 된다. 소견 줄은 §4 에 그대로 두고, §3 줄의 "§4 관련" 칸에 그 번호를 적는다.
3. **좋다와 싫다를 모두** 적는다.
4. 한 번 적은 줄은 지우거나 고치지 않는다. 생각이 바뀌면 **새 줄**을 더하고 "바뀐 줄" 칸에 옛 줄 번호를 적는다 — 읽는 쪽은 같은 대상의 **가장 나중 줄**을 따른다. **§4 의 줄과 어긋나는 §3 의 줄이 있으면 §3 이 이긴다** (줄의 앞뒤와 상관없이 — 사용자가 직접 요청한 것이 B 의 추론보다 앞선다). **§4 의 `B 소견` 줄끼리 어긋나는 것은 생각이 바뀐 것이 아니다** — 출력 B 는 Task·회차마다 다른 세션이므로, 나중 소견이 앞 소견을 대신하지 않는다. "바뀐 줄" 칸을 비우고 둘 다 남긴다 — 읽는 쪽은 B 의 소견이 갈린다는 사실을 본다.
5. 줄 번호는 섹션마다 따로 붙인다 — §3 은 `U1`·`U2`·…, §4 는 `B1`·`B2`·… (출력 B 보고서·레이아웃 문서가 이 번호로 가리킨다).
6. 어느 사용자의 취향인지는 "출처" 칸(프로젝트 · Task)으로 가른다. 이 파이프라인을 다른 사람이 쓰게 되면 읽는 쪽은 **자기 사용자의 줄만** 본다.
7. 쌓을 것이 없으면 줄을 더하지 않는다 — 그 사실을 호출 결과에 적는다.
