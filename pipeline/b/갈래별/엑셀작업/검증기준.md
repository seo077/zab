## 0. 이 문서가 보는 것과 안 보는 것

**보는 것** — 엑셀작업 파이프라인이 실제 Task에서 돌았을 때 나오는 산출물. 확정 사양(D-58 · D-59 수정분)에 따라 **두 단계의 산출물을 따로** 본다.

| 단계 | 산출물 (D-59 "구성"·"사람 확인") | 이 문서에서 보는 B | 보는 절 |
|---|---|---|---|
| ① **레이아웃 작업** | 레이아웃 문서(md) — 입력 읽기·분석 + 무엇을 어떤 모양으로 만들지/바꿀지 결정. 자리 = 설계 게이트의 `log/T{N}_<작업명>/설계명세.md` | **레이아웃 B** | §4 (LC · LT · LB) |
| ② **출력 작업** | 레이아웃 기반으로 만든 `output/` 작업본 xlsx + 수정 기록 파일(해당 Task output 안 별도 파일, 판본별 절) + 구현요약 | **출력 B** | §5 (OC · OT · OB) |

B 는 **두 번** 검증한다 (D-59 "에이전트"). 두 B 는 각자 자기 단계의 절만 본다.

**단계 차례와 기준 B** (D-61 G-16 — D-60 G-13 "Task 시작 때 한 번"을 대신한다 · 맨 앞 줄과 맨 끝 줄은 D-69 U-1 (가) · U-2 (가)):

```
(Z·사용자 협의 → ★ 사양 확정)
→ 레이아웃 기준 B → ★ 레이아웃 기준 승인 → 레이아웃 A → 레이아웃 B → ★ 설계(레이아웃) 승인
→ 출력 기준 B → (★ 출력 기준 승인 — Task 마다 선택 · 회색지대가 있으면 생략이어도 연다) → 출력 A → 출력 B → ★ 최종 수락
→ 취향 기록 B (★ 최종 수락 뒤 늘 한 번 — 쌓을 것이 있는지는 그 B 가 가린다)
```

- **맨 앞 협의 · ★ 사양 확정**은 정의(`z/pipelines/엑셀작업.md`) 단계표의 1 · ★ 줄이다 (D-69 U-1 (가) — 사용자가 그대로 두기로 정했다). 기준 B 가 대상물과 스킬을 찾는 "확정 사양"(§3.2 · §7 ②)이 여기서 나온다. 판정 단계가 아니므로 G-16 의 일곱 걸음에 세지 않는다.
- **검증 기준은 단계마다 그 단계 앞에서 쓴다.** 레이아웃 기준 B 는 사양·입력만 보고, 출력 기준 B 는 **승인된 레이아웃**까지 보고 그 단계의 합본을 쓴다 (§7). 기준을 쓰는 B 와 그 기준으로 판정하는 B 는 다른 호출이다 (`b/공통규칙.md` §7).
- **기준 승인 ★ 는 두 자리다** (D-62 G-18 (ㄱ)). ★ 레이아웃 기준 승인은 늘 받는다. ★ 출력 기준 승인은 **Task 마다 선택**이다 — ★ 레이아웃 기준 승인 자리에서 Z 가 "출력 기준 승인도 받을지 / 생략할지"를 묻고, 사용자의 답이 장부 확인지점에 남는다. 생략한 Task 에서는 그 답이 출력 합본을 쓰는 근거다 (§7 ①). 목적은 제3자 편의다 (사용자 말 — D-62). **단, 생략으로 정한 Task 라도 출력 기준 B 가 사람이 정할 회색지대를 올리면(합본을 멈춘 경우 포함) 그 Task 는 ★ 출력 기준 승인을 연다** (D-63 G-20 (ㄱ) — §7 ① 넷째 불릿).
- **★ 최종 수락 뒤 취향 기록 B** (D-63 G-21 (ㄴ) · D-69 U-2 (가)) — Z 가 **늘 한 번** 부르는 짧은 B 호출 하나가 장부 확인지점에 남은 사용자 말 원문을 `참고자료/사용자_취향.md` 에 옮겨 적고, **B 가 파악한 사용자 취향도** 적을 수 있다. 그 파일은 **두 섹션** — §3 사용자가 직접 요청한 것 / §4 B 의 추론(B 가 미루어 안 사용자 취향 + 출력 B 자신의 취향 소견) — 으로 나눠 적는다 (D-64 G-22 (ㄴ)). 판정하지 않는 호출이며 이 문서의 항목을 쓰지 않는다. 누가 · 무엇을 읽고 · 어떻게 적나는 그 파일 §1 · §2 에 있다. 쌓을 것이 있는지 가리는 것도 그 B 다 — 없으면 줄을 더하지 않고 그 사실을 돌려준다 (그 파일 §2 의 7).
- **판정 종합 단계(종합 B)는 두지 않는다.** 두 B 의 판정은 각자 다른 ★(설계 승인 · 최종 수락)의 재료다. 대신 **출력 B 가 표현(AI스럽지 않은 어휘) · 디자인 · 가독성 확인을 함께 한다** (D-61 G-17 → §5.1.7).

**안 보는 것**
- 파이프라인 정의(`z/pipelines/엑셀작업.md`)·A 규칙(`a/갈래별/엑셀작업/`) 자체 → 파이프라인신설 갈래 기준이 본다.
- 엑셀 안 **내용의 분야 사실**(회로 값·시험 판정값·업무 수치가 옳은가) → 분야마다 다르므로 갈래 항목이 아니다. Task 사양이 근거 자료를 정하면 **셋째 층(이번 Task 항목)** 으로 붙인다 (§6 후보 목록).
- 판정 낱말·판정 값·심각도의 뜻 → 공통층.

### 0.2 공통층과 겹치지 않게

공통층이 이미 보는 것(경로·빈 파일·판정 낱말·회차·경로 실재·경로 밖·M-N·장부·목적·써 보기·정합·원본 무손상의 뜻·비교 기준·보존 목록 절차·설계명세의 실행 수단 C-D1)은 **여기서 항목으로 다시 세우지 않는다.** 대신 §2 에 **"공통 항목을 엑셀작업에서 볼 때의 적용법"** 을 단계별로 적었다 — 항목이 아니라 적용 안내이며 항목 수에 세지 않는다. 적용법이 공통 항목과 어긋나 보이면 **공통이 이긴다** (`b/공통규칙.md` §9).

## 1. 판정 값·심각도·종합 규칙

이 갈래는 별도로 정의하지 않는다. **판정 값 세 갈래(통과/조건부/미달 · 문면 ⚠️ 포함)·심각도 세 등급(필수/권장/선택)·종합 판정 규칙은 `b/검증기준_공통.md` §1·§1.1·§2·§6 을 그대로 따른다.** 합본에는 그 원문을 함께 싣는다 (공통 §8).

이 갈래에서 유의할 것:
- 엑셀 산출물은 **사람이 셀 하나하나에 기대는 문서**(시험자·업체·설계자)다. 확인하지 못한 셀 범위는 통과 근거가 못 된다 — 표본으로 본 범위는 결과에 범위를 적는다 (공통 §6.3).
- **종합 판정은 단계마다 따로 낸다.** 레이아웃 B 의 종합은 레이아웃 문서에 대한 것이고, 출력 B 의 종합은 출력물에 대한 것이다. 한 단계의 결과를 다른 단계 종합에 섞어 세지 않는다. 두 종합을 합치는 종합 B 는 두지 않는다 (D-61 G-17).
- 출력 B 의 종합에는 표현·디자인·가독성 항목(§5.1.7)이 **같은 무게 규칙으로** 들어간다 — 따로 셈하지 않는다 (공통 §6 의 "권장 3건 이상 → ❌" 도 함께 센다 — **D-62 G-19 (ㄱ) 확정**: OC-20·22·23·24 권장 · OC-21 선택).
- **B 의 취향 소견은 판정에 넣지 않는다** (D-62). 보고서 X-N 메모로만 적는다. `참고자료/사용자_취향.md` 에는 ★ 최종 수락 뒤 **취향 기록 B** 가 사용자 말 원문(그 파일 §3 — 사용자가 직접 요청한 것)과, B 가 파악한 사용자 취향 · 출력 B 의 취향 소견(그 파일 §4 — B 의 추론)을 섹션을 나눠 옮긴다 (D-63 G-21 (ㄴ) · D-64 G-22 (ㄴ) — §0 · §5.1.7 머리말 · 그 파일 §1 · §2).
- **적용 조건(§3.3)에 걸리지 않는 항목**은 "해당 없음 (어느 조건이 아닌지)"으로 남기고 집계·종합에 세지 않는다 (공통 §4.1 C-D1 처리와 같은 방식).

- **이름 꼴 = 중첩형 `skills/<단계>/<대상물>`** (D-60 G-11 ⓐ). `<단계>` 폴더(`레이아웃/`·`출력/`)는 스킬을 묶는 폴더이고 그 자체가 스킬이 아니다. 이 꼴은 공통 규칙(`a/공통규칙.md` §7.2 · `b/공통규칙.md` §9)을 T6 안에서 고쳐 받아들이기로 했다 (D-60 범위 확장) — **이 문서의 꼴은 고친 규칙을 전제로 한다.** 고친 규칙이 다른 꼴을 정하면 그쪽이 이긴다 (`b/공통규칙.md` §9 "공통이 이긴다") — 그때는 이 절과 `skills/` 를 다음 회차에 맞춘다 (§11.1 X-9).
- **이름은 A·B 가 한 글자도 다르지 않게 짝짓는다** (D-59 "같은 이름으로 짝"). 짝을 맞추는 것은 경로 이름 `<단계>/<대상물>` 이다. 끝 모양(A 는 `.md` 파일 / 폴더 — `a/공통규칙.md` §7.2 · B 는 `.md` 파일 — 바로 아래 불릿)은 각자 규약대로이며 짝 판정에 넣지 않는다 (이 해석이 고친 규칙과 맞는지는 Task 방 기준이 본다).
- **항목(무엇을 볼지)은 이 문서에, 방법(어떻게 읽을지)은 `skills/` 에** 둔다 — `b/공통규칙.md` §9 (`검증기준.md` = 항목, `skills/` = 절차·도구 사용법) · **D-60 G-11 ⓑ 확정.** B 쪽 스킬 파일은 자기 항목 절을 가리킬 뿐 항목을 다시 적지 않는다 (같은 것이 두 곳에 있으면 어긋날 때 판별 불가). B 스킬은 판독 절차뿐이라 **파일 하나**(`<대상물>.md`, 첫 줄 머리표)로 둔다.

### 3.2 Task 가 스킬을 끌어오는 법

한 Task 는 **레이아웃 스킬 하나 이상 + 같은 대상물의 출력 스킬** 로 돈다 (예: 표 하나를 채우는 Task = `레이아웃/표` + `출력/표`. 표와 블록도를 함께 고치는 Task = 넷 다).

- **레이아웃 B** 에 거는 것 = §4.1 LC 전부 + 그 Task 가 쓴 레이아웃 스킬의 절(§4.2·§4.3).
- **출력 B** 에 거는 것 = §5.1 OC 전부(표현·디자인·가독성 OC-20~24 포함) + 그 Task 가 쓴 출력 스킬의 절(§5.2·§5.3).
- 어느 스킬을 쓰는지는 **Task 사양**에서 찾고, 레이아웃 문서가 확정한다(LC-2). 레이아웃 합본 때 사양에 대상물이 없거나 둘로 읽히면 회색지대로 올린다(추정해서 고르지 않는다). 출력 합본은 **승인된 레이아웃의 LC-2 결정**대로 출력 스킬 절을 고른다 (§7).

### 3.3 적용 조건 — 출발점 (r1 의 "작업 종류 넷"이 들어간 자리)

D-59 로 r1 의 작업 종류 넷은 두 단계에 나뉘어 들어갔다 — 읽기·분석과 기존 파일 편집의 "바꿀 내용 결정"은 **레이아웃**, 양식 채우기·신규 작성·기존 파일 편집의 "실제 적용"은 **출력**. 출력 쪽 셋은 대상물이 아니라 **출발점**이 다르므로, 스킬로 가르지 않고 항목의 **적용 조건**으로 둔다 (**D-60 G-12 확정** — "적용 조건으로 두겠습니다").

#### 5.1.7 표현 · 디자인 · 가독성 (OC-20 ~ OC-24) — 출력 B 가 함께 본다 (D-61 G-17)

> 사용자 결정 G-17: "종합 B 두고 싶은데, AI스럽지 않은 어휘적인 표현, 디자인과 가독성 측면을 확인하는 작업" → "출력 B에서 해당 작업을 같이 진행하는 방향으로 하겠습니다." 그래서 이 절은 **모든 출력 스킬에 건다** (대상물을 가리지 않는다).
> **대상 = 작업본 xlsx 안에서 사람이 읽는 것** — 셀 문자열 · 시트 이름 · 메모/댓글 · 도형·텍스트 상자 글자 · 셀·도형의 서식. 수정 기록 파일·구현요약은 작업 기록이라 대상이 아니다.
> **[바탕]이면 이번 Task 가 만들거나 바꾼 범위만** 센다 (OC-14 변경 집합 · OB-1 차분 · 새 시트). 바탕에 원래 있던 문장·서식은 보존 대상(OC-8)이므로 지적 대상이 아니다 — 눈에 띄면 X-N 메모로만 적는다.
> **판정하는 것은 사실뿐이다.** "어색하다·예쁘지 않다"(취향)는 판정하지 않는다 — 패턴 사전에 걸리는 문자열, 같은 역할인데 다른 서식, 잘리는 글자처럼 **위치를 대고 셀 수 있는 것**만 판정한다. 고쳐 쓴 문장·서식을 대신 제시하지 않는다 (V-1).
> **취향 소견 (D-62)** — B 의 취향 소견(좋다·싫다 — "색 조합이 거슬린다" · "머리 행 강조가 보기 좋다" 등)은 **판정에 넣지 않는다.** 보고서의 X-N 메모에 "취향 소견" 묶음으로 따로 적는다(대상 위치 · 좋다/싫다 · 한 줄 까닭). `참고자료/사용자_취향.md` 에 같은 대상의 줄이 있으면 그 번호(§3 `U<n>` / §4 `B<n>`)를 함께 적는다 — 그 파일은 **참고만** 하고 판정 근거로 쓰지 않는다 (I-5). 출력 B 는 그 파일에 쓰지 않는다 — ★ 최종 수락 뒤 **취향 기록 B** 가 장부의 사용자 말 원문은 그 파일 §3(사용자가 직접 요청한 것)에, **이 소견 자체**와 이 소견에 대한 사용자의 반응 등에서 B 가 파악한 사용자 취향은 §4(B 의 추론)에 옮긴다 — 그래서 소견은 그것만 읽어도 대상 위치 · 좋다/싫다 · 까닭을 알 수 있게 적는다(취향 기록 B 는 산출물을 다시 열지 않는다) (D-63 G-21 (ㄴ) · **D-64 G-22 (ㄴ)** · 그 파일 §1 · §2 · §10.6).

## 6. 셋째 층 후보 — 갈래가 아니라 Task 사양에 따라 붙는 것

## 7. 합칠 때(합본) 지킬 것 — 이 갈래 고유

공통 §8 에 더해:

1. **합본은 단계마다 그 단계 앞에서 쓴다** (**D-61 G-16** — D-60 G-13 "Task 시작 때 한 번, 두 단계 모두 담아"를 대신한다). 두 번 쓰고, 쓰는 B 가 다르다.

   | 합본 | 언제 | 쓰는 B | 쓰는 파일 | 담는 것 | 읽는 것 |
   |---|---|---|---|---|---|
   | **레이아웃 합본** | 레이아웃 A 앞 (★ 사양 확정 뒤 첫 B 단계 — D-69 U-1 (가)) | 레이아웃 기준 B | `log/T{N}_<작업명>/검증기준.md` (목차 + 판정 값·심각도·종합 규칙 원문 + 두 단계 파일 안내) · `log/T{N}_<작업명>/검증기준_레이아웃.md` | 공통층의 레이아웃 적용(§2.1) + LC 전부 + 그 Task 레이아웃 스킬 절 + 셋째 층 레이아웃분 + 입력 실측값(④) + 그 Task 레이아웃 B 스킬의 **판독 방법 구획**(②) | Task 사양 · 입력 · 이 문서 · 그 Task 가 쓰는 레이아웃 B 스킬(`skills/레이아웃/<대상물>.md`)과 그 스킬이 가리킨 `참고자료/` 절 · 공통층 |
   | **출력 합본** | ★ 설계(레이아웃) 승인 뒤, 출력 A 앞 | 출력 기준 B | `log/T{N}_<작업명>/검증기준_출력.md` | 공통층의 출력 적용(§2.2) + OC 전부(OC-20~24 포함) + 승인된 레이아웃이 정한 출력 스킬 절 + 셋째 층 출력분 + 승인 레이아웃에서 옮긴 기대값(⑤) + 그 출력 B 스킬의 **판독 방법 구획**(②) | Task 사양 · 입력 · **승인된 레이아웃** · `검증기준.md`(목차) · 이 문서 · 그 Task 가 쓰는 출력 B 스킬(`skills/출력/<대상물>.md`)과 그 스킬이 가리킨 `참고자료/` 절 · 공통층 |

   - 이 나눔은 공통 §8 "너무 길어지면 — 층이 아니라 **대상으로** 나눈다"의 꼴이다. 판정 값·심각도·종합 규칙은 **목차 `검증기준.md` 에만** 싣고, 단계 파일은 그것을 가리킨다. 판정하는 B 는 `검증기준.md` + 자기 단계 파일 하나를 연다.
   - **한 파일에 주인 하나** — 목차 `검증기준.md` 는 레이아웃 기준 B 가 쓰고, 그때 `검증기준_출력.md` 를 "출력 단계 앞에서 출력 기준 B 가 쓴다"는 자리로 미리 적어 둔다. 출력 기준 B 는 **목차를 고치지 않는다.** 출력 단계에만 필요한 것은 전부 `검증기준_출력.md` 에 쓴다.
   - **각 합본 뒤의 사람 승인 자리** (D-62 G-18 (ㄱ)) — ★ 레이아웃 기준 승인은 늘 있다. ★ 출력 기준 승인은 **Task 마다 선택**이며, 받을지 생략할지는 ★ 레이아웃 기준 승인 자리에서 사용자가 정한다(Z 가 묻고 장부 확인지점에 적는다). 승인 여부의 기준은 장부 확인지점이다 (공통 §8).
     - 레이아웃 기준 B 는 목차 `검증기준.md` 에 이 선택의 **자리**를 한 줄 적어 둔다 — "출력 기준 승인 여부: ★ 레이아웃 기준 승인 자리에서 사용자가 정한다 · 기록 = 장부 확인지점" (답은 적지 않는다 — 그 B 가 쓸 때는 아직 정해지지 않았다).
     - 출력 기준 B 는 `검증기준_출력.md` 머리표에 **승인 방식**을 적는다 — "★ 출력 기준 승인 받음" 또는 "생략 — 장부 확인지점 <단계 이름> · <일자> · 사용자 말" (장부를 직접 읽고 옮긴다) 또는 "생략이었으나 회색지대가 있어 ★ 를 엶 — G-<번호>" (아래 넷째 불릿). 장부에 선택 기록이 없으면 생략으로 보지 않고, 받는 것으로 적고 그 사실을 결과에 알린다.
     - 출력 B 는 판정을 시작할 때 이 머리표와 장부 확인지점을 대본다 — **생략한 Task 에서는 "★ 레이아웃 기준 승인 자리의 생략 결정"이 `b/부팅.md` ② 의 "사람 승인을 받은 파일"을 대신한다** (사용자 최종 결정 — `b/공통규칙.md` I-6 끝 줄). 그 사실을 보고서 "근거로 쓴 기준" 줄에 적는다. 다만 머리표가 "회색지대가 있어 ★ 를 엶"이면 생략 결정은 승인을 대신하지 못한다 — 장부에 그 ★ 의 승인 기록이 있어야 판정을 시작한다 (없으면 멈추고 알린다).
     - **생략으로 정했는데 출력 기준 B 가 사람이 정할 회색지대를 올렸다면(합본을 멈춘 경우 — ⑤ ⓐ 포함) 그 Task 는 ★ 출력 기준 승인을 연다** (D-63 G-20 (ㄱ)). 생략은 "기준을 사람이 보지 않아도 된다"는 결정이지, 사람이 정할 일을 B 가 대신 정해도 된다는 결정이 아니다. 출력 기준 B 는 회색지대를 `b/공통규칙.md` §7.1 네 축으로 파일 안에 모으고 결과에 "생략 Task 지만 ★ 가 필요하다"를 적는다 — ★ 를 여는 것은 Z 다. 회색지대가 없으면 생략대로 간다.
   - 레이아웃 R2 처럼 레이아웃 단계 안에서 다시 돌 때 기준은 다시 쓰지 않는다 — 기준을 바꿀 일이 생기면 새 리비전 + 승인 (공통 §8 "승인 뒤").
2. **스킬을 먼저 확정한다** — 레이아웃 합본은 Task 사양에서 대상물과 쓸 레이아웃 스킬(§3.1)을 찾아 머리에 적는다. 사양에 대상물이 없거나 둘로 읽히면 회색지대로 올린다(추정해서 고르지 않는다). 출력 합본은 **승인된 레이아웃의 LC-2 결정**에서 출력 스킬을 고른다 — 사양과 어긋나 보이면 회색지대로 올린다. **고른 스킬마다 판독 방법을 옮겨 싣는다** (`b/공통규칙.md` §9.3 ① ⑶ · "합본에 싣는 판독 방법") — 기준 B 는 같은 이름의 B 스킬을 열어 그 단계 파일(`검증기준_레이아웃.md` / `검증기준_출력.md`)에 항목과 따로 **판독 방법 구획**을 두고, 출처 `b/갈래별/엑셀작업/skills/<단계>/<대상물>` 와 옮겨 온 파일의 경로 · md5 를 머리에 적는다. 싣는 것은 스킬 본문 전부 · 스킬이 가리킨 `참고자료/` 절(파일 통째가 아니다) · 빌려 쓴 다른 B 스킬의 차례(예: `출력/블록도` ⑩ → `출력/표` ③~⑥ · ⑫ ⓓ → `출력/표` ⑫ ⓓ)다. 이 Task 에 맞추는 것은 해당 없는 차례를 "해당 없음 (이유)" 로 남기는 것과 자리표시 채우기뿐이다. 판정 B 는 `skills/` 를 열지 않는다.
3. **적용 조건(§3.3)대로** 해당 없는 항목은 지우지 말고 "해당 없음 (어느 조건이 아닌지)"로 남기고 집계에서 뺀다. 출발점([바탕]/[양식]/[신규]) · [병합] · [COM] · [문서] 는 레이아웃 합본에서는 사양으로 잠정 표시하고, 출력 합본에서는 **승인된 레이아웃 기준으로 확정**한다.
4. **레이아웃 합본은 입력에서 직접 잰다** — 바탕을 실측해(부품 목록 · 병합 수 · 인쇄 설정 · 정의된 이름 · 채움색 분포) 박아 두면, 레이아웃 B 는 LC-9·LC-11 을 그 값과 댄다. 산출물이 나오기 전이므로 입력만 연다 (T10 §B-2 방식).
5. **출력 합본은 승인된 레이아웃에서 기대값을 옮겨 박는다** — 레이아웃은 이 Task 의 설계이므로 출력 기준의 출처가 된다 (`b/공통규칙.md` §4.1 "설계 → 검증 기준 → 산출물 평가"). 옮길 것: ⓐ **승인된 레이아웃 문서의 SHA-256** (OC-2 의 기준값. 레이아웃 B 보고서 기재값과 다르면 그 사이 고친 판이 승인됐다는 장부 기록을 함께 적고, 기록이 없으면 합본을 멈추고 회색지대로) ⓑ 보존 목록(LC-9)을 바탕에서 다시 잰 값 ⓒ 표시 색 RGB · 수정 기록 파일 이름·자리 · 이번 판본(LC-11) ⓓ 시트 목록 · 모집단 수 · 변경 건수처럼 OC-13 이 하나씩 찾을 결정 목록의 자리(절·번호) ⓔ 비워 둘 칸·병합 계획처럼 출력 스킬 절이 가리키는 목록의 자리. **레이아웃 내용이 옳은지는 다시 따지지 않는다**(레이아웃 B 와 ★ 의 몫) — 출력 합본은 옮겨 적기만 하고, 옮기다 레이아웃의 빈칸·모순을 보면 회색지대로 올린다.
6. 근거 자료가 분야 사실을 담으면 §6 후보에서 셋째 층 항목을 뽑는다 — 결정의 근거 쪽은 레이아웃 합본, 실현값 쪽은 출력 합본에 넣는다 (§6 "단계" 칸).
7. 출력 합본에는 **§5.1.7 표현·디자인·가독성 항목을 빼지 않는다** (G-17). 사용자가 이 Task 에서 따로 피하라고 한 낱말이 있으면 §6 "표현 패턴의 Task 고유 추가" 를 셋째 층으로 더한다.

## 8. 확장 — 새 대상물 · 새 단계를 더할 때 (D-59 "확장")

> D-59: "다른 새 형태의 작업(새 대상물·새 단계)에 대해 파이프라인과 에이전트가 발전할 수 있도록 열어 둔다." 이 문서 쪽에서 무엇을 더하면 되는지를 정해 둔다. **기존 절은 고치지 않는다** (§4.1 LC · §5.1 OC 는 모든 스킬에 자동으로 걸린다).

### 8.1 새 대상물 (예: 차트 · 피벗 · 서식 문서)

이 문서에 **절 두 개**, `skills/` 에 **파일 두 개**를 더한다.

```
§4.N 레이아웃/<대상물> (L?-1 ~ L?-n)
> 이 스킬의 목적: <한 줄>. 출력/<대상물>(§5.N)이 이것을 그대로 실현했는지 본다.
| # | 항목 | 심각도 | 적용 | 어떻게 보나 | 출처 |

§5.N 출력/<대상물> (O?-1 ~ O?-n)
> 이 스킬의 목적: <한 줄>. 수정 기록에서 이 대상물을 어떻게 표시하나: <셀 색 / 기록만>.
| # | 항목 | 심각도 | 적용 | 어떻게 보나 | 출처 |

skills/레이아웃/<대상물>.md   skills/출력/<대상물>.md   (§3.1 형식 — 머리표 + 판독 절차 + 항목 절 가리킴.
                                                          b/공통규칙.md §9.1 대로 — 참고자료는 파일과 절까지 가리키고,
                                                          다른 스킬 차례는 스킬 경로 이름과 차례 번호로 빌리고,
                                                          합본에 그대로 옮겨도 혼자 읽히게)
```

- 이름은 A 쪽 스킬과 **한 글자도 다르지 않게** (§3.1 — 경로 이름 `<단계>/<대상물>`). 기존 `<단계>` 폴더 안에 파일 하나를 더하는 것이 전부다. 머리글자는 기존(`LC`·`LT`·`LB`·`OC`·`OT`·`OB`)과 겹치지 않게 고른다.
- 짝 원칙: 레이아웃 절의 "정해졌다" 항목마다 출력 절에 "그대로 실현됐다" 항목이 하나씩 대응되게 쓴다 (레이아웃에서 정하지 않은 것을 출력에서 볼 잣대가 없어지지 않게).
- 항목은 그 대상물의 **사양·합의·참고 사례**에서 뽑고 출처를 붙인다 (P-1). 더하는 것도 B 가 쓰고, ★ 사용자 승인을 받는다.
- §3.1 스킬 지도 · §11.4 항목 수 표에 한 줄씩 더한다.

### 8.2 새 단계 (예: 레이아웃과 출력 사이 시범 출력 · 출력 뒤 전달용 정리본)

- 단계 하나 = `§N <단계> 단계` 큰 절 하나 + 그 안에 `<단계> 공통` 절 + 대상물별 절. `skills/` 에는 `<단계>/` 묶음 폴더 하나를 더하고 그 안에 대상물별 파일을 둔다. 그 단계의 B 와 **그 단계 앞의 기준 B** 가 새로 생기므로(G-16 — 기준은 단계마다 그 단계 앞에서) §0 표·차례 · §3.1 · §7 ① 표(합본 · `검증기준_<단계>.md`)에 한 줄씩 더한다.
- 새 단계의 산출물이 무엇이고 무엇을 잣대로 보는지(앞 단계 산출물인가 · 사양인가)를 그 단계 공통 절 머리에 적는다.
- 새 단계는 파이프라인 정의(단계표)와 함께 바뀌어야 하므로 **파이프라인신설 또는 개선 회차**로 다룬다 — 이 문서만 먼저 고치지 않는다.

## 9. 회색지대 — 이 갈래에서 판정 때 조심할 자리

> 처리 원칙은 공통 §7 · `b/공통규칙.md` §6.5 를 따른다. 여기는 엑셀작업에서 자주 부딪힐 자리만.

| 상황 | 어떻게 |
|---|---|
| 착수 시 `~$` 잠금 파일이 있다 | 판정을 시작하지 않고 그 사실을 돌려준다 (OC-5). 잠금을 지우지 않는다 |
| 떠 있는 Excel 이 있다 (사용자 것일 수 있다) | PID 만 적고 손대지 않는다. 판독은 사본으로 (OC-6) |
| **출력이 레이아웃과 같은데, 레이아웃 자체가 근거와 어긋난다** (예: 레이아웃이 정한 값이 근거 자료와 다름) | 출력 B 는 OC-13 을 통과로 두고, 근거 대조 항목(OT-7 등)의 결과를 그대로 적는다 — 한쪽으로 조용히 정하지 않는다. 결함이 레이아웃 몫임을 밝히고 `[규칙과 실판정이 다름]` 블록으로 올린다. 레이아웃을 고칠지는 사용자 결정 |
| **레이아웃이 승인 뒤 바뀌었다** (OC-2 지문 불일치) | 판정을 멈추고 알린다. 바뀐 레이아웃이 다시 승인됐는지는 장부·호출문 MR-3 으로 본다 — 승인 기록 없이 바뀐 레이아웃을 잣대로 쓰지 않는다 |
| 출력 A 가 레이아웃과 다르게 했고 그 편이 더 나아 보인다 | 그래도 OC-13 이탈이다. 이탈 사실과 B 의 견해를 함께 적고, 받아들일지는 사용자 결정 |
| Excel 재저장으로 XML 이 대량으로 달라졌다 | 뜻 같은 재직렬화와 실변경을 가려낸 근거를 적는다. 가려내지 못한 범위는 못 본 것 — 해당 항목 통과를 주지 않는다 (OB-1 · OC-17) |
| 기록에 `''` 와 `None` 이 섞여 집합 수가 세는 법에 따라 갈린다 | 어느 쪽으로 셌는지 밝히고, 갈리는 칸을 X-N 메모로 적는다 (T10 B2_R1 X-4) |
| 표시 색을 지운 칸 · 값은 같고 색만 바뀐 칸 | 색 변화도 변경이다 — 기록이 있거나 표시 규칙(예: 확인 필요 해제)으로 설명돼야 한다 (OC-16) |
| A 의 빌드 스크립트로 재현성을 보고 싶다 | 실행하지 않는다 (지정 경로를 덮어쓸 수 있다). 재현성은 못 본 것으로 적는다 |
| 수정 기록 근거 칸에 검증 보고서 번호·파이프라인 낱말이 있다 | C-3 문맥 판단. 판정 결과가 아니라 출처 표기면 메모로 두되, 사람에게 가는 파일이면 사용자 격상 여지를 §6.5 블록으로 적는다 (T10 B2_R2 §4) |
| 규칙 두 개가 부딪힌다 (예: "풀린 확인 필요는 표시를 지운다" ↔ "답안 질문은 열린 상태로 둔다") | 어느 한쪽으로 조용히 정하지 않는다. 결함이 어느 항목의 몫인지 밝히고 `[규칙과 실판정이 다름]` 블록으로 올린다 (T10 B2_R1 §4) |
| 검증기준 파일 머리 "상태"가 "승인 대기"로 남아 있다 | 승인 여부는 장부(`log/manifest.json`)와 호출문 MR-3 으로 본다 (공통 §8) |
| 표현 패턴(OC-20)에 걸렸지만 근거 자료 원문 인용이거나, 대체어로 바꾸면 뜻이 달라진다 | 사전 §2 의 제외 사유에 해당하면 건마다 사유를 적고 뺀다. 사유가 "어색하지 않다"(취향)면 빼지 않는다 (T6 §9) |
| 디자인·가독성이 눈에는 걸리는데 위치를 대고 셀 수 있는 결함이 아니다 (색 조합이 거슬린다 등) | 판정하지 않는다. X-N 메모의 "취향 소견" 묶음으로 적고(`참고자료/사용자_취향.md` 에 같은 대상 줄이 있으면 번호를 함께), 사용자가 ★ 최종 수락 때 볼 거리로 남긴다 — 그 뒤 취향 기록 B 가 이 소견을 취향 파일 §4(B 의 추론)에 옮기고, 사용자가 반응했으면 그 반응도 적는다 (§5.1.7 머리말 · D-62 · D-63 G-21 · D-64 G-22) |
| 취향 파일의 줄과 산출물이 어긋난다 (사용자가 싫다고 한 서식이 쓰였다 등) | 판정하지 않는다 — 그 Task 사양이 그 줄을 지키라고 정해 셋째 층 항목이 된 경우(§6)만 판정한다. 아니면 X-N "취향 소견"에 줄 번호와 위치만 적는다 (D-62 "출력 B 참고만") |
| [바탕] 원래 문장·서식이 표현 패턴·디자인 일관에 걸린다 | 이번 Task 가 바꾸지 않은 범위면 지적하지 않는다 — 보존 대상(OC-8)이다. 메모로만 |

### 11.2 이 기준이 못 본 것 · 한계

- **산출물이 없을 때 쓴 기준이다.** 엑셀작업 파이프라인으로 만든 산출물은 아직 없다. 항목은 D-58·D-59 와 TDSCU 사례의 검증 관점에서만 뽑았고, 실제로 굴려 봐야 드러날 빈틈(항목이 너무 무겁거나 확인 수단이 없는 것)이 있을 수 있다.
- **레이아웃 단계는 사례가 없다.** TDSCU 에는 "레이아웃 문서를 먼저 승인받고 출력하는" 판이 없었다 — LC·LT·LB 는 TDSCU 의 출력 쪽 관점(무엇이 정해져 있었어야 판정이 섰나)을 앞 단계로 옮겨 쓴 것이다. 첫 실사용 Task 뒤 다시 볼 필요가 크다.
- **블록도 신규 작성 사례가 없다.** TDSCU T6 은 기존 블록도 편집이었다. OB-1 의 [신규] 부분과 LB-2 는 사례 없이 사양에서 뽑았다.
- **A 규칙(`a/갈래별/엑셀작업/규칙.md`)·A 스킬이 아직 없다** (3단계 몫). 백업 이름·기록 파일 꼴 같은 구체 형식은 X-2 대로 4단계에서 대조한다.
- TDSCU 의 T1~T4 엑셀 실적(R7-이어서가 언급)은 이번 의뢰의 재료 목록에 없어 열지 않았다.
- 참고 사례 문서는 기준·보고서 본문을 읽었다 (r1 에서 전체 · r2 에서는 T6 검증기준의 BD-S·T·G·C·L·N 절과 T10 검증기준 T10-9·13·15~17 행을 다시 열어 대조). 사례의 산출 xlsx 자체는 열지 않았다 (기준을 만드는 단계이고, 사례 결론을 옮기지 않기 위해서다).
- 이 기준을 쓰며 도구로 쓴 것: Read(문서 직접 열람) · Bash(`cat`·`sed -n`·`grep -n`·`ls -la`·`find`·`md5sum`·`mv`). r3 에서는 이 문서와 `skills/` 를 고치려고 짧은 치환 스크립트(`py -3 -I`, 문자열 치환만)를 썼다. 판독용으로 실행한 스크립트는 없다.
- **r3 는 사용자 결정(D-60) 반영 회차다.** TDSCU 참고 사례는 r1·r2 에서 읽은 것을 그대로 두었고 r3 에서 다시 열지 않았다 — 새로 더한 항목이 없기 때문이다(항목 수 그대로). 바뀐 것은 이름 꼴 · G-10 결정의 문면 · 결정 대기 표기 · X-N 이다.
